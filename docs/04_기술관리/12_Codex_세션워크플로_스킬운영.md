# Codex 세션 워크플로 스킬 운영

## 목적

PDFowers 작업에서 반복되는 세션 마무리, 브랜치 승급, 세션 종료 절차를 Codex 스킬과 저장소 문서로 함께 관리한다.

로컬 Codex 스킬은 실제 자동 적용을 위한 실행 지침이고, 이 문서는 저장소에서 추적하는 운영 기준이다.

## 로컬 스킬 위치

현재 실행용 스킬은 다음 경로에 둔다.

```text
C:\Users\jkoog\.codex\skills\pdfowers-session-workflow\SKILL.md
```

Codex는 기본적으로 `C:\Users\jkoog\.codex\skills` 아래의 스킬을 자동 발견한다.

저장소 안의 이 문서만 수정하면 Codex 스킬에는 자동 반영되지 않는다. 절차가 바뀌면 실행용 스킬 파일과 이 문서를 함께 갱신한다.

## 스킬명

```text
pdfowers-session-workflow
```

## 트리거

다음 사용자 요청이 들어오면 스킬을 적용한다.

- `#세션마무리`
- `#브랜치승급`
- `#세션종료`

## #세션마무리 절차

1. 세션번호를 유지한 채 세션 과정에서 진행한 작업 내용을 기반으로 세션명을 바꾼다.
   - 형식: `세션번호-작업내용`
   - 예: `15-운영도메인검증기준정리`
2. 세션 내 작업한 내용으로 리뷰 문서를 작성한다.
   - 위치: `docs/10_리뷰관리/YYYYMM/DD/`
   - 리뷰 문서에는 작업 요약, 변경 파일, 검증 내용, 후속 작업, 관련 이슈/PR을 포함한다.
3. GitHub 이슈를 등록하거나 기존 이슈를 갱신한다.
   - 이슈 제목과 본문은 한글로 작성한다.
   - 신규 이슈는 생성 후 발급된 번호를 제목 앞에 표시하도록 제목을 갱신한다.
   - 예: `#74 세션 워크플로 트리거 정리`
4. 작업 브랜치를 push하고 `dev` 대상 PR을 작성한다.
   - PR 제목은 한글로 작성한다.
   - PR 제목에는 해당 이슈 번호를 포함한다.
   - 예: `세션 워크플로 트리거 정리 (#74)`
   - PR 본문에는 작업 요약, 변경 파일, 검증 내용, 후속 작업을 포함한다.
   - 완료 대상 이슈가 있으면 `Closes #번호`를 포함한다.
5. 세션 작업에 해당하는 문서 현행화 대상을 점검하고 반영한다.
   - 운영 기준: `docs/04_기술관리/`
   - 이슈/잔여작업: `docs/08_이슈관리/`
   - 리뷰 산출물: `docs/10_리뷰관리/`
   - 하네스/프로젝트 산출물: `docs/00_산출물/`
   - 스킬 변경: 실행용 스킬 파일과 이 문서를 함께 갱신한다.

검증은 변경 범위에 맞춰 수행하되, 일반적으로 아래를 우선한다.

```powershell
git diff --check
npm run typecheck
npm run test:unit
npm test
npm run build
```

문서와 스킬만 변경한 경우에는 `git diff --check`와 관련 키워드 검색을 우선 수행한다. 코드 테스트가 불필요하면 그 이유를 리뷰 문서와 최종 보고에 적는다.

## #브랜치승급 절차

1. 원격 상태를 갱신하고 현재 브랜치 상태를 확인한다.
   - `git fetch origin`
   - `git status --short --branch`
2. 작업 PR 또는 로컬 작업을 `dev`에 병합한다.
3. `dev -> stg`를 직접 머지한다. 별도 승급 PR은 작성하지 않는다.
4. `stg -> main`을 직접 머지한다. `main`은 GitHub 기본 운영 브랜치이며 서비스 관점의 prd에 해당한다. 별도 승급 PR은 작성하지 않는다.
5. 승급 머지 메시지에는 이슈번호와 원천 PR번호를 표시한다.
   - 예: `승급: dev to stg - 세션 워크플로 정리 (#74, PR #75)`
   - 예: `승급: stg to main - 세션 워크플로 정리 (#74, PR #75)`
6. 브랜치를 점검한다.
   - 원격 `dev`, `stg`, `main`의 commit SHA, 제목, tree hash를 확인한다.
   - 로컬 `main`이 `origin/main`과 같은지 확인한다.
   - 최종적으로 `origin/dev`, `origin/stg`, `origin/main`, 로컬 `main`의 tree hash가 같은지 확인한다.
7. 세션 내 작업한 이슈의 완료 조건을 확인하고 닫는다.
   - 작업 PR 또는 이슈 본문에 연결 관계가 명확해야 한다.
   - 남은 작업이 있으면 닫지 않고 이유와 후속 범위를 최종 보고에 적는다.
8. 최종 보고에는 병합한 PR/이슈 번호, 승급 머지 SHA, 브랜치 점검 결과, 닫은 이슈 번호를 포함한다.

확인 예시:

```powershell
git show -s --format="%h%n%H%n%T%n%s" origin/dev
git show -s --format="%h%n%H%n%T%n%s" origin/stg
git show -s --format="%h%n%H%n%T%n%s" origin/main
git rev-parse main
git rev-parse origin/main
```

## #세션종료 절차

세션 종료는 문서를 새로 작성하지 않고 채팅 답변으로만 다음 세션 전달 내용을 남긴다.

답변에는 다음을 포함한다.

1. 다음 세션명
   - 형식: `세션번호-작업내용`
2. MVP 남은 작업 현황 점검
3. 다음 세션에서 진행할 업무 범위
4. 이어서 확인해야 할 이슈, PR, 문서 링크

`#세션종료`는 커밋, PR, 이슈 생성, 문서 작성을 수행하지 않는다. 필요한 작업이 남아 있으면 `#세션마무리` 또는 별도 작업 지시로 분리한다.

## 운영 기준

- 실행용 스킬은 로컬 Codex 기본 경로에서 관리한다.
- 저장소 공유용 절차는 이 문서에서 관리한다.
- 스킬 내용이 바뀌면 이 문서도 같이 갱신한다.
- 이 문서만 변경해도 Codex 스킬 자동 적용에는 반영되지 않는다. 실행용 스킬 파일을 함께 수정해야 한다.
