# 브랜치 승급 절차

## 목적

`dev`, `stg`, `main` 브랜치 승급 순서와 결과 기록 위치를 표준화한다. `main`은 GitHub 기본 운영 브랜치이며 서비스 관점의 prd에 해당한다. 승급 결과는 관련 이슈 댓글에 남기고, 결과 기록만을 위한 추가 문서 커밋과 재승급은 반복하지 않는다.

## 기본 원칙

- 모든 작업 PR은 `dev` 브랜치를 대상으로 생성한다.
- 이슈, 리뷰 문서, 세션 마무리 문서 등 작업 산출물은 먼저 작업 PR을 통해 `dev`에 반영한다.
- `dev` 반영이 끝난 뒤 `dev -> stg`를 직접 머지한다.
- `stg` 반영이 끝난 뒤 `stg -> main`을 직접 머지한다.
- `dev -> stg`, `stg -> main` 승급을 위한 별도 GitHub PR은 작성하지 않는다.
- 승급 머지 메시지에는 관련 이슈 번호와 원천 작업 PR 번호를 표시한다.
- 승급 결과의 원천 PR 번호, 승급 머지 커밋 SHA, 검증 결과는 관련 이슈 댓글에 기록한다.
- `main` 승급까지 완료된 뒤 완료 조건을 충족한 연결 이슈는 `completed` 사유로 닫는다.
- 승급 완료 후 결과 기록만을 위한 추가 커밋과 재승급은 원칙적으로 수행하지 않는다.

## 세션 마무리와 승급 순서

1. 작업 리뷰 문서를 작성한다.
2. 관련 이슈를 등록하거나 기존 이슈를 갱신한다.
3. 작업 PR을 생성하고 `dev`에 병합한다.
4. `dev -> stg`를 직접 머지한다.
5. `stg -> main`을 직접 머지한다.
6. 승급 머지 메시지에 이슈번호와 원천 PR번호를 표시한다.
7. 승급 결과를 관련 이슈 댓글에 기록한다.
8. 원격 `dev`, `stg`, `main`과 로컬 `main`의 commit/tree 상태를 확인한다.
9. 완료 조건을 충족한 연결 이슈를 닫는다.
10. 닫지 않은 이슈가 있으면 닫지 않은 이유와 남은 범위를 최종 보고에 남긴다.

## 승급 머지 메시지 형식

```text
승급: dev to stg - 작업명 (#이슈번호, PR #원천PR번호)
승급: stg to main - 작업명 (#이슈번호, PR #원천PR번호)
```

예:

```text
승급: dev to stg - 세션 워크플로 정리 (#74, PR #75)
승급: stg to main - 세션 워크플로 정리 (#74, PR #75)
```

## 승급 결과 기록 형식

이슈 댓글에는 최소한 다음 정보를 포함한다.

| 항목 | 내용 |
| :--- | :--- |
| 작업 PR | `task/* -> dev` PR 번호와 병합 여부 |
| 승급 머지 | `dev -> stg`, `stg -> main` 머지 커밋 SHA |
| 최종 커밋 | `dev`, `stg`, `main`의 최종 커밋 SHA |
| 브랜치 점검 | 원격 `dev`, `stg`, `main`과 로컬 `main`의 commit/tree 일치 여부 |
| 검증 결과 | 주요 테스트, 빌드, 문서 확인 결과 |
| 후속 작업 | 남은 작업 또는 없음 |

## 브랜치 점검 기준

승급 후 다음을 확인한다.

1. 원격 `dev`, `stg`, `main`의 최신 commit SHA, 제목, tree hash
2. 로컬 `main`과 `origin/main`의 SHA 일치 여부
3. 원격 `dev`, `stg`, `main`과 로컬 `main`의 tree hash 일치 여부

확인 예시:

```powershell
git fetch origin
git show -s --format="%h%n%H%n%T%n%s" origin/dev
git show -s --format="%h%n%H%n%T%n%s" origin/stg
git show -s --format="%h%n%H%n%T%n%s" origin/main
git rev-parse main
git rev-parse origin/main
```

## 이슈 종료 기준

`main` 승급까지 완료된 뒤 다음 조건을 모두 만족하면 연결 이슈를 닫는다.

1. 작업 PR 또는 이슈 본문에 연결 관계가 명확하다.
2. 이슈 본문의 완료 조건이 충족됐다.
3. 남은 작업이 없거나 별도 후속 이슈/작업으로 분리됐다.
4. 승급 결과 댓글에 원천 PR 번호, 주요 커밋 SHA, 검증 결과를 기록했다.

연결 이슈가 여러 개면 각 이슈별로 완료 조건을 확인한다. 완료된 이슈는 모두 닫고, 미완료 이슈는 열어 둔다.

다음 경우에는 이슈를 닫지 않는다.

- 연결 이슈가 명확하지 않다.
- 이슈 본문 또는 댓글에 아직 완료되지 않은 범위가 남아 있다.
- 검증이 실패했거나 검증을 수행하지 못했다.
- 운영 판단, 외부 환경 적용, 사용자 확인 등 남은 작업이 이슈의 핵심 완료 조건이다.

닫지 않은 이슈는 최종 보고에 이유와 남은 작업을 적는다.
