# 브랜치 승급 절차

## 목적

`dev`, `stg`, `main` 브랜치 승급 순서와 결과 기록 위치를 표준화한다. 승급 결과는 이슈 댓글에 남기고, 결과 기록만을 위한 후속 문서 커밋과 재승급을 반복하지 않는다.

## 기본 원칙

- 모든 작업 PR은 `dev` 브랜치를 대상으로 생성한다.
- 이슈, 리뷰 문서, 세션 마무리 문서 등 작업 산출물은 먼저 작업 PR을 통해 `dev`에 반영한다.
- `dev` 반영이 끝난 뒤 `dev -> stg` 승급 PR을 1회 생성한다.
- `stg` 반영이 끝난 뒤 `stg -> main` 승급 PR을 1회 생성한다.
- 승급 결과의 최종 PR 번호, 커밋 SHA, 검증 결과는 관련 이슈 댓글에 기록한다.
- 승급 완료 후 결과 기록만을 위한 추가 커밋과 재승급은 원칙적으로 수행하지 않는다.

## 세션 종료 순서

1. 작업 리뷰 문서를 작성한다.
2. 관련 이슈를 등록하거나 기존 이슈를 갱신한다.
3. 작업 PR을 생성하고 `dev`에 병합한다.
4. 필요한 경우 `dev -> stg` 승급 PR을 생성하고 병합한다.
5. 필요한 경우 `stg -> main` 승급 PR을 생성하고 병합한다.
6. 승급 결과를 관련 이슈 댓글에 기록한다.
7. 세션 고유정보는 이슈 번호를 기준으로 관리한다.

## 승급 결과 기록 형식

이슈 댓글에는 최소한 다음 정보를 남긴다.

| 항목 | 내용 |
| :--- | :--- |
| 작업 PR | `task/* -> dev` PR 번호와 병합 여부 |
| 승급 PR | `dev -> stg`, `stg -> main` PR 번호와 병합 여부 |
| 최종 커밋 | `dev`, `stg`, `main`의 최종 커밋 SHA |
| 검증 결과 | 주요 테스트, 빌드, 문서 확인 결과 |
| 후속 작업 | 남은 작업 또는 없음 |

## 기존 기록 처리

`docs/10_리뷰관리/202606/09/260609_02_브랜치승급_dev-stg-main.md`는 승급 결과를 문서로 남긴 예외 사례로 보존한다. 해당 문서를 소급 삭제하거나 재작성하지 않으며, 이후 승급에서는 이 패턴을 반복하지 않는다.
