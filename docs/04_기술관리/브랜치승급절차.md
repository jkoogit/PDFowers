# 브랜치 승급 절차

## 목적

`dev`, `stg`, `main` 브랜치 승급 순서와 결과 기록 위치를 표준화한다. 승급 결과는 관련 이슈 댓글에 남기고, 결과 기록만을 위한 추가 문서 커밋과 재승급은 반복하지 않는다.

## 기본 원칙

- 모든 작업 PR은 `dev` 브랜치를 대상으로 생성한다.
- 이슈, 리뷰 문서, 세션 마무리 문서 등 작업 산출물은 먼저 작업 PR을 통해 `dev`에 반영한다.
- `dev` 반영이 끝난 뒤 `dev -> stg` 승급 PR을 1개 생성한다.
- `stg` 반영이 끝난 뒤 `stg -> main` 승급 PR을 1개 생성한다.
- 승급 결과의 최종 PR 번호, 커밋 SHA, 검증 결과는 관련 이슈 댓글에 기록한다.
- `main` 승급까지 완료된 뒤 완료 조건을 충족한 연결 이슈는 `completed` 사유로 닫는다.
- 승급 완료 후 결과 기록만을 위한 추가 커밋과 재승급은 원칙적으로 수행하지 않는다.

## 세션 종료와 승급 순서

1. 작업 리뷰 문서를 작성한다.
2. 관련 이슈를 등록하거나 기존 이슈를 갱신한다.
3. 작업 PR을 생성하고 `dev`에 병합한다.
4. 필요한 경우 `dev -> stg` 승급 PR을 생성하고 병합한다.
5. 필요한 경우 `stg -> main` 승급 PR을 생성하고 병합한다.
6. 승급 결과를 관련 이슈 댓글에 기록한다.
7. 완료 조건을 충족한 연결 이슈를 닫는다.
8. 닫지 않은 이슈가 있으면 닫지 않은 이유와 남은 범위를 최종 보고에 남긴다.

## 승급 결과 기록 형식

이슈 댓글에는 최소한 다음 정보를 포함한다.

| 항목 | 내용 |
| :--- | :--- |
| 작업 PR | `task/* -> dev` PR 번호와 병합 여부 |
| 승급 PR | `dev -> stg`, `stg -> main` PR 번호와 병합 여부 |
| 최종 커밋 | `dev`, `stg`, `main`의 최종 커밋 SHA |
| 검증 결과 | 주요 테스트, 빌드, 문서 확인 결과 |
| 후속 작업 | 남은 작업 또는 없음 |

## 이슈 종료 기준

`main` 승급까지 완료된 뒤 다음 조건을 모두 만족하면 연결 이슈를 닫는다.

1. 작업 PR 또는 승급 PR이 이슈를 `Closes #번호`, `Fixes #번호`, `Resolves #번호`로 연결했거나, PR/이슈 본문에 연결 관계가 명확하다.
2. 이슈 본문의 완료 조건이 충족됐다.
3. 남은 작업이 없거나 별도 후속 이슈/작업으로 분리됐다.
4. 승급 결과 댓글에 최종 PR 번호, 주요 커밋 SHA, 검증 결과를 기록했다.

연결 이슈가 여러 개면 각 이슈별로 완료 조건을 확인한다. 완료된 이슈는 모두 닫고, 미완료 이슈는 열어 둔다.

다음 경우에는 이슈를 닫지 않는다.

- 연결 이슈가 명확하지 않다.
- 이슈 본문 또는 댓글에 아직 완료되지 않은 범위가 남아 있다.
- 검증이 실패했거나 검증을 수행하지 못했다.
- 운영 판단, 외부 환경 적용, 사용자 확인 등 남은 작업이 이슈의 핵심 완료 조건이다.

닫지 않은 이슈는 최종 보고에 이유와 남은 작업을 적는다.
