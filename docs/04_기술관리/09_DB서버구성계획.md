# 09. DB 서버 구성 계획

## 목적

MVP1 개발, 검증, 운영 후보 환경에서 사용할 PostgreSQL 서버 구성 기준을 정리한다. 초기 DB 서버는 로컬 네트워크의 우분투 노트북에 Docker 기반 PostgreSQL로 구성하고, 앱 서비스는 NAS Docker 또는 운영 배포 서비스에서 접속하는 구조를 전제로 한다.

## 구성 전제

| 항목 | 값 |
| :--- | :--- |
| DB 서버 후보 | 로컬 네트워크 우분투 노트북 |
| DB 서버 IP | `192.168.219.125` |
| DB 실행 방식 | Docker 컨테이너 |
| DB 엔진 | PostgreSQL 17 + pgvector |
| 초기 백업 위치 | 우분투 로컬 디스크 |
| 후속 백업 검토 | NAS 백업 프로세스 추가 검토 |
| 운영 배포 후보 | Cloudtype 또는 대체 무료/저가 서비스 |

운영 서비스가 외부 클라우드에 올라가는 경우 우분투 노트북 DB를 운영 DB로 장기 사용하면 네트워크, 전원, 절전, 회선 장애 위험이 있다. 따라서 운영 전에는 Cloud DB 또는 안정적인 VPS/VM 기반 DB로 전환하는 방안을 재검토한다.

## 환경별 DB 포트와 계정

| 환경 | 브랜치 기준 | DB 포트 | DB 계정 | Docker 볼륨명 | DB명 후보 |
| :--- | :--- | :---: | :--- | :--- | :--- |
| 개발 | `dev` | `35432` | `devdbusr` | `postgreDev` | `pdfowers_dev` |
| 검증 | `stg` | `45432` | `stgdbusr` | `postgreStg` | `pdfowers_stg` |
| 운영 | `main` | `55432` | `prddbusr` | `postgrePrd` | `pdfowers_prd` |

포트는 호스트 노출 포트 기준이다. 컨테이너 내부 PostgreSQL 포트는 기본 `5432`를 유지하고, Docker 포트 매핑으로 환경별 포트를 분리한다.

```text
35432 -> dev PostgreSQL container:5432
45432 -> stg PostgreSQL container:5432
55432 -> prd PostgreSQL container:5432
```

오픈 전 개발과 검증 단계에서는 개발 자유도를 우선하여 `192.168.219.125` 로컬 네트워크 IP에 포트를 바인딩한다. 서비스 오픈 전에는 NAS IP 또는 앱 서버 IP만 허용하도록 방화벽 정책과 접근 경로를 재정비한다.

## Docker 구성 방향

초기에는 환경별 PostgreSQL 컨테이너를 분리한다.

```text
/opt/pdfowers/postgres/
  dev/
    docker-compose.yml
    .env
    backup/
  stg/
    docker-compose.yml
    .env
    backup/
  prd/
    docker-compose.yml
    .env
    backup/
```

볼륨은 Docker named volume을 우선 사용한다.

| 환경 | 볼륨 |
| :--- | :--- |
| 개발 | `postgreDev` |
| 검증 | `postgreStg` |
| 운영 | `postgrePrd` |

운영 전에는 named volume만 사용할지, 명시 bind mount로 백업 경로를 단순화할지 재검토한다.

## Compose 초안

아래는 개발 환경 예시다. 검증/운영은 포트, 계정, 볼륨, DB명만 분리한다.

```yaml
services:
  postgres-dev:
    image: pgvector/pgvector:pg17
    container_name: pdfowers-postgres-dev
    restart: unless-stopped
    ports:
      - "192.168.219.125:35432:5432"
    environment:
      POSTGRES_DB: pdfowers_dev
      POSTGRES_USER: devdbusr
      POSTGRES_PASSWORD: ${POSTGRES_PASSWORD}
      TZ: Asia/Seoul
    volumes:
      - postgreDev:/var/lib/postgresql/data
      - ./backup:/backup
      - ./init:/docker-entrypoint-initdb.d:ro
    healthcheck:
      test: ["CMD-SHELL", "pg_isready -U devdbusr -d pdfowers_dev"]
      interval: 10s
      timeout: 5s
      retries: 5

volumes:
  postgreDev:
    name: postgreDev
```

주의: 실제 비밀번호는 `.env`에만 기록하고 문서, 이슈, PR, 로그에 남기지 않는다.

## 벡터 DB 기준

PDFowers가 향후 문서 검색, AI 검색, 임베딩 기반 유사도 검색을 사용할 가능성이 있으므로 PostgreSQL 이미지에는 `pgvector` 확장을 포함한다.

| 항목 | 기준 |
| :--- | :--- |
| Docker 이미지 | `pgvector/pgvector:pg17` |
| PostgreSQL 메이저 | 17 |
| 확장 | `vector` |
| 초기화 SQL | `CREATE EXTENSION IF NOT EXISTS vector;` |

각 환경의 초기화 SQL은 다음 위치에 둔다.

```text
/opt/pdfowers/postgres/dev/init/001_vector_extension.sql
/opt/pdfowers/postgres/stg/init/001_vector_extension.sql
/opt/pdfowers/postgres/prd/init/001_vector_extension.sql
```

`vector` 확장은 DB 초기 생성 시 적용된다. 이미 데이터 볼륨이 생성된 후 확장 SQL을 추가한 경우에는 컨테이너 내부에서 수동으로 `CREATE EXTENSION IF NOT EXISTS vector;`를 실행해야 한다.

## 접속 문자열 기준

앱 컨테이너의 환경변수는 환경별로 분리한다.

```text
DATABASE_URL=postgresql://devdbusr:${DB_PASSWORD}@192.168.219.125:35432/pdfowers_dev
DATABASE_URL=postgresql://stgdbusr:${DB_PASSWORD}@192.168.219.125:45432/pdfowers_stg
DATABASE_URL=postgresql://prddbusr:${DB_PASSWORD}@192.168.219.125:55432/pdfowers_prd
```

실제 `.env` 파일에서는 `${DB_PASSWORD}` 형식이 아니라 환경별 비밀번호 원문을 넣되, 저장소에는 커밋하지 않는다.

## 방화벽과 접근 제어

DB 포트는 인터넷에 공개하지 않는다. 오픈 전에는 개발 편의를 위해 로컬 네트워크 IP에 바인딩할 수 있으나, 서비스 오픈 전에는 NAS 앱 서버 IP와 관리 PC IP만 허용한다.

예시:

```bash
sudo ufw allow from <NAS_IP> to any port 35432 proto tcp
sudo ufw allow from <NAS_IP> to any port 45432 proto tcp
sudo ufw allow from <NAS_IP> to any port 55432 proto tcp
sudo ufw deny 35432/tcp
sudo ufw deny 45432/tcp
sudo ufw deny 55432/tcp
sudo ufw enable
sudo ufw status
```

운영 DB 포트 `55432`는 운영 전까지 외부 클라우드 서비스에서 직접 접근하지 않는 것을 기본으로 둔다. 외부 운영 서비스가 로컬 DB에 접근해야 하는 경우 VPN, Tailscale, WireGuard 같은 사설망 연결을 먼저 검토한다.

## 백업 초안

초기 백업은 우분투 로컬 디스크에 보관한다.

```text
/opt/pdfowers/postgres-backup/
  dev/
  stg/
  prd/
```

백업 명령 후보:

```bash
docker exec pdfowers-postgres-dev pg_dump -U devdbusr -d pdfowers_dev > /opt/pdfowers/postgres-backup/dev/pdfowers_dev_$(date +%Y%m%d_%H%M%S).sql
```

후속 운영 전략에서 다음을 검토한다.

1. NAS로 백업 파일 복사
2. 최근 7일 또는 14일 보관 정책
3. 주기적 복구 테스트
4. 운영 DB 외부 이전 시 백업/복구 절차 재작성
