# 카카오 간편로그인 연동 매뉴얼

## 목적

PDFowers MVP1 검수 서버에서 카카오 간편로그인을 실제 카카오 OAuth로 검증하기 위한 설정 절차를 정리한다.

이 문서는 2026-06-11 로컬 검수에서 실제로 성공한 설정을 기준으로 한다.

## 검증 완료 상태

- 카카오 앱: `PDFriend`
- REST API 키 이름: `PDFowers.rest-dev`
- 로컬 Redirect URI: `http://localhost:4173/auth/kakao/callback`
- 검수 서버 URL: `http://localhost:4173/`
- 검증 결과: 카카오 로그인 성공 후 `kakao` AuthIdentity 생성 확인
- MVP1 체크: `MVP1-AUTH-T006` 통과

## 서버 구현 경로

검수 서버는 다음 엔드포인트를 제공한다.

| 메서드 | 경로 | 용도 |
| --- | --- | --- |
| `GET` | `/auth/kakao/config-status` | 카카오 환경변수 설정 상태 확인 |
| `GET` | `/auth/kakao/start` | 카카오 OAuth 인가 URL로 리다이렉트 |
| `GET` | `/auth/kakao/callback` | 카카오 인가 코드 수신, 토큰 교환, 사용자 정보 조회, 로그인 처리 |

카카오 access token, refresh token, authorization code, client secret은 DB나 검수화면 상태에 저장하지 않는다.

## 로컬 환경변수

로컬 `.env`에 설정한다. `.env`는 `.gitignore` 대상이므로 Git에 커밋하지 않는다.

```dotenv
KAKAO_REST_API_KEY=카카오_REST_API_키
APP_BASE_URL=http://localhost:4173
KAKAO_REDIRECT_PATH=/auth/kakao/callback
KAKAO_SCOPE=
KAKAO_CLIENT_SECRET=카카오_로그인_Client_Secret
```

런타임은 `APP_BASE_URL`과 `KAKAO_REDIRECT_PATH`를 조합해 카카오 Redirect URI를 만든다. 도메인을 바꿀 때는 일반적으로 `APP_BASE_URL`만 변경한다.

```text
APP_BASE_URL=https://jkok2.myqnapcloud.com:4443
KAKAO_REDIRECT_PATH=/auth/kakao/callback
=> https://jkok2.myqnapcloud.com:4443/auth/kakao/callback
```

기존 배포와의 호환을 위해 `KAKAO_REDIRECT_URI`를 직접 지정하면 그 값을 우선 사용한다. 신규 배포에서는 `KAKAO_REDIRECT_URI` 대신 `APP_BASE_URL`을 기준으로 관리한다.

### Scope 설정 기준

초기 검수에서는 `KAKAO_SCOPE`를 비워둔다.

```dotenv
KAKAO_SCOPE=
```

카카오 콘솔의 `동의항목`에서 이메일과 닉네임 항목을 설정한 뒤에만 아래처럼 켠다.

```dotenv
KAKAO_SCOPE=account_email,profile_nickname
```

동의항목을 설정하지 않은 상태에서 scope를 요청하면 `KOE205`가 발생한다.

## 카카오 콘솔 설정 절차

### 1. 앱 선택

1. Kakao Developers에 로그인한다.
2. 앱 목록에서 `PDFriend` 앱을 선택한다.
3. 앱 ID와 앱 이름이 맞는지 확인한다.

### 2. REST API 키 설정

왼쪽 메뉴에서 다음 경로로 이동한다.

```text
앱 설정 > 앱 > 플랫폼 키
```

키 목록에서 `REST API 키`를 선택한다. 이번 검수에서는 `PDFowers.rest-dev` 키를 사용했다.

REST API 키 수정 화면에서 다음을 확인한다.

- REST API 키 값이 서버 `.env`의 `KAKAO_REST_API_KEY`와 동일해야 한다.
- 카카오 로그인 Redirect URI는 이 REST API 키 화면에 등록해야 한다.
- JavaScript 키 화면에 Redirect URI를 등록해도 서버 REST 로그인에는 적용되지 않는다.

### 3. 카카오 로그인 Redirect URI 등록

`REST API 키 수정` 화면의 `카카오 로그인 리다이렉트 URI`에 등록한다.

로컬 검수:

```text
http://localhost:4173/auth/kakao/callback
```

개발 도메인:

```text
https://fowersdev.pdfrend.com/auth/kakao/callback
```

스테이징/운영 후보:

```text
https://fowersstg.pdfrend.com/auth/kakao/callback
https://fowers.pdfrend.com/auth/kakao/callback
```

운영 위치가 NAS인지 Cloudtype인지 확정되기 전에도 운영 도메인을 NAS prd 후보에 연결할 수 있다. 이 경우에도 Kakao Developers에는 실제 브라우저가 접근하는 운영 도메인 기준 callback URI를 등록한다. 호스팅 위치가 나중에 Cloudtype으로 바뀌더라도 callback URI가 같은 운영 도메인을 유지하면 카카오 설정은 바꾸지 않아도 된다.

입력 후 반드시 화면 오른쪽 아래의 `저장`을 누른다.

### 4. JavaScript SDK 도메인 등록

JavaScript SDK를 사용할 경우에만 필요하다. 현재 서버 REST OAuth 검수에는 직접 필요하지 않지만, 프론트에서 Kakao JavaScript SDK를 쓸 가능성이 있으므로 함께 등록해 둔다.

경로:

```text
앱 설정 > 앱 > 플랫폼 키 > JavaScript 키 수정
```

`JavaScript SDK 도메인`에 등록한다.

```text
http://localhost:4173
https://fowersdev.pdfrend.com
https://fowersstg.pdfrend.com
https://fowers.pdfrend.com
```

주의: 이 화면의 Redirect URI 등록은 JavaScript 키 기준이다. 서버가 `KAKAO_REST_API_KEY`로 로그인 요청을 보내는 경우 REST API 키 화면에도 같은 Redirect URI를 별도로 등록해야 한다.

### 5. Client Secret

`REST API 키 수정` 화면의 `클라이언트 시크릿`에서 확인한다.

이번 검수에서는 `카카오 로그인` Client Secret이 `ON`이었다. 이 경우 서버 `.env`에 `KAKAO_CLIENT_SECRET`을 반드시 설정해야 토큰 교환이 통과한다.

```dotenv
KAKAO_CLIENT_SECRET=카카오_로그인_Client_Secret
```

Client Secret이 OFF라면 `KAKAO_CLIENT_SECRET`은 비워도 된다. 운영과 stg에서는 ON을 권장한다.

### 6. 동의항목

경로:

```text
제품 설정 > 카카오 로그인 > 동의항목
```

초기 검수는 scope 없이 먼저 성공시킨다. 이메일과 닉네임을 실제로 받고 싶으면 동의항목에서 사용 설정을 완료한 뒤 `KAKAO_SCOPE`를 켠다.

이메일은 카카오 정책과 앱 상태에 따라 제한될 수 있다.

## 로컬 서버 재시작

```powershell

```

백그라운드로 실행한 기존 서버가 있으면 종료 후 다시 시작해야 한다. 설정 반영 여부는 다음으로 확인한다.

```text
http://localhost:4173/auth/kakao/config-status
```

정상 예:

```json
{
  "enabled": true,
  "missing": [],
  "redirectUri": "http://localhost:4173/auth/kakao/callback",
  "scope": "",
  "clientSecretConfigured": true
}
```

## 검수 방법

1. PC 브라우저에서 `http://localhost:4173/`에 접속한다.
2. `카카오 로그인 시작`을 누른다.
3. 카카오 로그인과 동의를 진행한다.
4. 성공하면 `/auth/kakao/callback` 처리 후 검수화면 `/`으로 복귀한다.
5. 검수화면에서 Kakao 로그인 성공 메시지와 현재 사용자 상태를 확인한다.
6. `MVP1-AUTH-T006`이 `passed`인지 확인한다.

검수 화면 또는 API 상태에서 확인할 핵심 값은 다음과 같다.

```json
{
  "ok": true,
  "user": {
    "loginId": "kakao-{providerUserId}",
    "displayName": "Kakao {providerUserId}",
    "identities": [
      {
        "provider": "kakao",
        "providerUserId": "{providerUserId}"
      }
    ]
  }
}
```

scope 없이 검수하면 이메일과 닉네임이 내려오지 않을 수 있다. 이 경우 서버는 `kakao-{providerUserId}@kakao.local.test` 형태의 임시 이메일과 `Kakao {providerUserId}` 표시명을 사용한다.

## 오류 대응

### KOE006

오류:

```text
등록하지 않은 리다이렉트 URI
```

원인:

- 서버가 사용한 `redirect_uri`가 REST API 키 화면에 등록되어 있지 않다.
- JavaScript 키 화면에만 Redirect URI를 등록했다.
- `.env`의 `KAKAO_REST_API_KEY`와 Redirect URI를 등록한 키가 다르다.
- 저장 버튼을 누르지 않았다.

해결:

1. `앱 설정 > 앱 > 플랫폼 키`로 이동한다.
2. `REST API 키` 중 서버 `.env`의 `KAKAO_REST_API_KEY`와 같은 키를 연다.
3. `카카오 로그인 리다이렉트 URI`에 `http://localhost:4173/auth/kakao/callback`을 등록한다.
4. 저장한다.
5. 검수 서버를 재시작하거나 `/auth/kakao/start`를 다시 호출한다.

### KOE205

오류:

```text
설정하지 않은 카카오 로그인 동의 항목을 포함해 인가 코드를 요청했습니다.
```

원인:

- `KAKAO_SCOPE=account_email,profile_nickname`으로 요청했지만 카카오 콘솔 동의항목에서 해당 항목을 설정하지 않았다.

해결:

초기 검수에서는 scope를 비운다.

```dotenv
KAKAO_SCOPE=
```

이메일/닉네임이 필요하면 `제품 설정 > 카카오 로그인 > 동의항목`에서 항목을 설정한 뒤 scope를 다시 켠다.

### 토큰 교환 실패

가능 원인:

- Client Secret이 ON인데 `.env`의 `KAKAO_CLIENT_SECRET`이 비어 있다.
- Client Secret 값이 카카오 로그인용 코드와 다르다.
- REST API 키와 Client Secret이 서로 다른 키에서 가져온 값이다.

해결:

`REST API 키 수정` 화면의 `클라이언트 시크릿 > 카카오 로그인` 코드 값을 `.env`의 `KAKAO_CLIENT_SECRET`에 설정한다.

## 로컬과 모바일 테스트 차이

`localhost`는 접속한 기기 자신을 의미한다.

- PC 브라우저에서 `http://localhost:4173`: 가능
- 휴대폰 브라우저에서 `http://localhost:4173`: 불가
- 휴대폰 카카오톡 앱 기반 테스트: `https://fowersdev.pdfrend.com`처럼 휴대폰에서 접근 가능한 HTTPS 도메인이 필요

## 도메인 운영 제안

현재 구매 도메인 `pdfrend.com` 기준 권장 구성:

| 환경 | 도메인 | 용도 |
| --- | --- | --- |
| dev | `https://fowersdev.pdfrend.com` | 개발 검수 |
| stg | `https://fowersstg.pdfrend.com` | 배포 전 검증 |
| prod | `https://fowers.pdfrend.com` | 운영 |

운영 호스팅 위치는 NAS와 Cloudtype 중 추후 결정한다. 결정 전까지 운영 도메인은 NAS prd 후보에 연결하고, 앱은 `APP_ENV=prd`, `APP_BASE_URL=https://fowers.pdfrend.com`, `KAKAO_REDIRECT_PATH=/auth/kakao/callback` 기준으로 실행한다. 앱 코드에는 NAS 전용 분기를 추가하지 않는다.

가능하면 카카오 앱 또는 REST API 키도 dev/stg/prod로 분리한다.

## 보안 기준

- REST API 키, Client Secret, DB 비밀번호는 Git, 이슈, PR, 문서에 원문으로 남기지 않는다.
- `.env`는 Git에 커밋하지 않는다.
- OAuth access token, refresh token은 MVP1에서 저장하지 않는다.
- 운영/stg에서는 Client Secret을 활성화한다.
- 운영 도메인은 HTTPS를 사용한다.
- 정상 공인 도메인과 인증서 체인을 사용하면 Node smoke test는 별도 CA 설정 없이 통과해야 한다.
- `NODE_EXTRA_CA_CERTS`는 dev smoke test의 인증서 체인 진단 보조 옵션으로만 사용하고, 서비스 운영 조건으로 삼지 않는다.
- `NODE_TLS_REJECT_UNAUTHORIZED=0`은 기본 검증 절차로 사용하지 않는다.

## 2026-06-19 운영 도메인과 검증 기준

Kakao 실제 로그인 완료 플로우는 Codex 자동 브라우저 검증이 아니라 운영자가 직접 브라우저에서 수동 검증한다. 자동 smoke test는 `/auth/kakao/config-status`와 `/auth/kakao/start`까지만 확인한다.

수동 검증 항목:

1. 운영자가 브라우저에서 환경별 URL에 접속한다.
2. `카카오 로그인 시작`을 누른다.
3. 카카오 계정 로그인과 동의를 직접 수행한다.
4. callback 처리 후 검수화면 `/`으로 복귀하는지 확인한다.
5. 세션이 발급되고 현재 사용자 상태가 표시되는지 확인한다.
6. 계정 통합 요청 카드가 요청 계정, 대상 계정, provider, 상태, 승인 후 안내를 표시하는지 확인한다.

환경별 callback URI는 실제 접속 도메인 기준으로 등록한다.

```text
https://fowersdev.pdfrend.com/auth/kakao/callback
https://fowersstg.pdfrend.com/auth/kakao/callback
https://fowers.pdfrend.com/auth/kakao/callback
```

임시로 QNAP DDNS를 사용하는 dev 환경은 아래 callback URI도 함께 등록한다.

```text
https://jkok2.myqnapcloud.com:4443/auth/kakao/callback
```

운영 도메인을 NAS prd 후보에 연결하더라도 Kakao 기준은 NAS가 아니라 도메인이다. 나중에 Cloudtype으로 이전해도 `https://fowers.pdfrend.com/auth/kakao/callback`을 유지하면 OAuth callback 정책은 그대로 사용할 수 있다.

Node smoke test에서만 인증서 체인 문제가 발생하면 먼저 실제 도메인 인증서가 full chain으로 제공되는지 확인한다. 그래도 dev smoke 보조가 필요하면 실행 환경에서만 `NODE_EXTRA_CA_CERTS`를 지정한다.

```powershell
$env:NODE_EXTRA_CA_CERTS="D:\certs\dev-ca-chain.pem"
npm run review:kakao-smoke -- --base-url https://fowersdev.pdfrend.com
```

이 설정은 테스트 실행 옵션이며 앱 코드나 운영 배포 요구사항이 아니다.
## 2026-06-17 dev NAS 우선 기준

dev NAS 서비스는 우선 `https://jkok2.myqnapcloud.com:4443`을 기준 URL로 사용한다.

```dotenv
APP_BASE_URL=https://jkok2.myqnapcloud.com:4443
KAKAO_REDIRECT_PATH=/auth/kakao/callback
```

카카오 개발자 콘솔의 REST API Redirect URI에는 다음 값을 등록한다.

```text
https://jkok2.myqnapcloud.com:4443/auth/kakao/callback
```

Codex 로컬 샌드박스와 IntelliJ 실행은 root `.env.example`을 기준으로 `APP_BASE_URL=http://localhost:4173`을 사용한다. 이 경우 카카오 개발자 콘솔에는 `http://localhost:4173/auth/kakao/callback`도 함께 등록되어 있어야 한다.

배포 후 검증은 다음 명령을 사용한다.

```powershell
npm run review:kakao-smoke -- --base-url https://jkok2.myqnapcloud.com:4443
```

내부망에서 `jkok2.myqnapcloud.com:4443`이 열리지 않으면 hairpin NAT 미지원 가능성을 우선 확인한다. 내부 DNS 또는 개발 PC `hosts`에서 `jkok2.myqnapcloud.com -> 192.168.219.112`로 매핑하되, 브라우저 주소와 카카오 Redirect URI는 계속 `https://jkok2.myqnapcloud.com:4443` 기준으로 유지한다.

### 콜백 후 timeout 대응

카카오 계정 입력 후 `/auth/kakao/callback?code=...&state=...` 주소에서 오래 멈추면 NAS 컨테이너가 외부 카카오 API에 접근하지 못하는지 먼저 확인한다. 서버는 token/profile 요청을 8초 안에 실패 처리하도록 제한한다.

NAS에서 확인할 명령은 다음과 같다.

```bash
docker logs pdfowers_dev --tail 100
docker exec -it pdfowers_dev node -e "fetch('https://kauth.kakao.com').then(r=>console.log(r.status)).catch(e=>console.error(e))"
docker exec -it pdfowers_dev node -e "fetch('https://kapi.kakao.com').then(r=>console.log(r.status)).catch(e=>console.error(e))"
```

`KAKAO_TOKEN_REQUEST_TIMEOUT`이면 token 교환 단계에서, `KAKAO_PROFILE_REQUEST_TIMEOUT`이면 사용자 프로필 조회 단계에서 외부 HTTPS 요청이 지연된 것이다. 이때 NAS 컨테이너 DNS, outbound 443, QNAP 방화벽, 공유기 보안 설정을 확인한다.

### 2026-06-17 dev request-host Redirect URI

dev 환경에서는 `APP_ENV=dev`와 `KAKAO_ALLOWED_REDIRECT_ORIGINS`를 사용해 접속 Host별 Kakao Redirect URI를 만들 수 있다.

```dotenv
APP_ENV=dev
APP_BASE_URL=https://jkok2.myqnapcloud.com:4443
KAKAO_REDIRECT_PATH=/auth/kakao/callback
KAKAO_ALLOWED_REDIRECT_ORIGINS=http://localhost:4173,http://127.0.0.1:4173,http://192.168.219.112:4173,https://jkok2.myqnapcloud.com:4443
```

위 설정에서 `http://192.168.219.112:4173`으로 로그인 시작 시 callback은 `http://192.168.219.112:4173/auth/kakao/callback`을 사용한다. `https://jkok2.myqnapcloud.com:4443`으로 시작하면 callback도 `https://jkok2.myqnapcloud.com:4443/auth/kakao/callback`을 사용한다.

Kakao Developers REST API Redirect URI에는 dev에서 허용할 callback URI를 모두 등록한다. `stg`와 `prd`는 request-host 방식을 사용하지 않고 `APP_BASE_URL` 기준 고정 Redirect URI를 사용한다.
