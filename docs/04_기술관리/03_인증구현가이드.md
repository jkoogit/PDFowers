# 03. 인증 구현 가이드

## 목적

하네스 기반 신규 프로젝트에서 ID 계정, 카카오/네이버/구글 간편로그인, 로그인 수단 연결, 계정 통합을 구현하기 위한 기술 기준을 정리한다.

## 인증 범위

| 구분 | MVP 처리 |
| :--- | :--- |
| ID 계정 | 구현 |
| 카카오 로그인 | MVP1 실제 연동 |
| 네이버 로그인 | MVP1 실제 연동 대상 |
| 구글 로그인 | MVP1 실제 연동 대상 |
| 휴대폰 본인인증 | 제외 |
| 실명확인 | 제외 |

## 환경변수

실제 값은 문서에 기록하지 않는다.

```text
KAKAO_CLIENT_ID=
KAKAO_CLIENT_SECRET=
KAKAO_REDIRECT_URI=

NAVER_CLIENT_ID=
NAVER_CLIENT_SECRET=
NAVER_REDIRECT_URI=

GOOGLE_CLIENT_ID=
GOOGLE_CLIENT_SECRET=
GOOGLE_REDIRECT_URI=

SESSION_SECRET=
DATABASE_URL=
```

## OAuth 콜백 처리 원칙

1. 제공자 OAuth 인증을 완료한다.
2. 토큰 교환 후 제공자 사용자 정보를 조회한다.
3. 제공자 사용자 고유 ID를 `provider_user_id`로 저장한다.
4. 이메일은 회원가입/로그인 인증, 사용자 화면 인증, 계정 식별 보조, 작업 알림 발송 대상으로 사용하되 자동 통합의 단독 근거로 사용하지 않는다.
5. `(provider, provider_user_id)` 기준으로 내부 연결 이력을 조회한다.

## 로그인 처리

```text
provider_user_id가 기존 AuthIdentity에 있음
  -> 연결된 user_uuid로 로그인

provider_user_id가 없음
  -> 로그인 흐름이면 회원가입으로 안내
  -> 회원가입 흐름이면 신규 User 생성
  -> AuthIdentity 생성
  -> 로그인 또는 가입 완료
```

ID/이메일 로그인은 시스템 설정에 따라 이메일 인증을 필수 또는 선택으로 처리한다.

- 이메일 인증 필수 여부는 시스템 속성으로 관리한다. 현재 DB 모델에는 시스템 속성 테이블이 없으므로 MVP1 구현 시 `system_property` 같은 정책 저장 구조를 추가 검토한다.
- 이메일 인증 필수 설정이면 회원가입 과정에 이메일 인증 절차를 포함한다.
- 운영 중 정책이 필수로 변경된 뒤 미인증 사용자가 로그인하면 로그인 자체는 허용하되 사용자정보 수정 화면으로 이동시켜 이메일 인증 안내와 인증 기능을 제공한다.
- 사용자정보 수정 화면으로 이동한 뒤 인증 없이 다른 화면으로 이동하는 것은 허용한다. 정책 변경 안내 메시지를 계속 노출할지는 별도 운영 정책으로 결정한다.
- 이메일 인증 선택 설정이면 회원가입 시 이메일 인증 옵션과 알림 수신 안내를 제공하고, ID 로그인은 이메일 미인증 상태에서도 허용한다.
- 간편로그인은 제공자 인증 결과를 사용하므로 PDFowers 이메일 인증 없이 로그인할 수 있다. 이메일 인증은 기본적으로 알림 수신 신뢰 수단이며, 시스템 설정에 따라 ID 로그인 보조 인증 단계로만 추가될 수 있다.
- 이메일 미인증 상태에서도 서비스 사용은 차단하지 않는다. 다만 이메일 알림 발송 대상에서는 제외한다.
- 이메일 인증 완료 전 재발송하면 앞서 발급한 인증번호 또는 인증 토큰은 폐기한다.
- 인증번호 또는 인증 토큰 만료 시간은 1시간으로 한다.
- 재발송 기본 정책은 사용자+이메일 기준 60초 쿨다운, 1시간 최대 5회 발송, 인증번호 1건당 실패 확인 5회 제한으로 시작한다. 운영 중 과도하거나 부족하면 시스템 설정으로 조정한다.
- 인증 완료 전용 화면은 만들지 않고 회원가입 화면과 사용자정보 수정 화면 안에서 진행/완료 상태를 표시한다.

## 인증 수단 관리 기준

- 기본 로그인 정보는 ID/PW이며 사용자가 임의 삭제할 수 없다.
- 계정 삭제는 인증 수단 삭제가 아니라 탈퇴 절차로 처리한다.
- 카카오, 네이버, 구글 간편로그인은 모두 연결 해제할 수 있다.
- 이메일 인증 필수 설정에서 인증 완료 이메일은 삭제할 수 없다.
- 이메일 변경은 새 이메일 인증이 완료된 뒤 기존 이메일 정보를 교체한다.
- 이메일 인증 선택 설정에서도 알림 수신 대상 이메일은 인증 완료 상태를 우선 사용한다.

## 로그인 수단 연결 처리

```text
현재 로그인 user_uuid = A01
연결 요청 provider_user_id = kakao01

kakao01 연결 이력 없음
  -> A01에 연결

kakao01이 A01에 이미 연결됨
  -> AUTH_IDENTITY_ALREADY_LINKED

kakao01이 A02에 연결됨
  -> ACCOUNT_MERGE_REQUIRED
  -> 요청자에게 안내 메시지와 `통합 요청 보내기` 버튼 표시
  -> 요청자가 버튼을 누르면 대상 계정에 계정 통합 요청 발송
  -> 요청자 사용자정보 화면에 통합계정 목록 표시
  -> 대상 계정 로그인 후 사용자정보 화면에서 승인/거절/삭제 처리
```

## 계정 통합 구현 기준

- 통합은 서버 트랜잭션으로 처리한다.
- 대표 계정을 정하고, 보조 계정 데이터를 대표 계정으로 이전한다.
- `AuthIdentity.user_uuid`를 대표 계정으로 변경한다.
- 보조 `User.user_status_cd`는 `MERGED`로 변경한다.
- `merged_into_user_uuid`에 대표 계정 내부 식별자를 저장한다.
- 통합 이벤트는 `Audit` 도메인에 기록한다.
- 통합 정보 목록은 사용자정보 화면에 표시한다. 통합 요청이 한 건도 없으면 목록 영역을 표시하지 않는다.
- 요청자 목록 상태는 `요청`, `반려`, `완료`로 표시한다.
- 대상자 목록 상태는 `요청`, `거절`로 표시하고, 승인 후에는 대상 계정 로그인을 제한한다.
- 대상자 목록에는 `승인`, `거절`, `삭제` 버튼을 표시한다.
- 대상자가 삭제하면 자동 거절 처리한다.
- 요청자가 통합정보를 삭제하면 대상자 목록에서도 삭제한다.
- 통합 여부와 관계없이 요청자는 통합정보를 삭제할 수 있다.
- 승인 확인 메시지는 다음 문구를 사용한다.

```text
해당 계정의 자료와 활동은 A계정으로 이동하고 계정이 잠깁니다.
동의하시겠습니까?
```

- 통합 완료 또는 잠긴 보조 계정 로그인 시 다음 문구를 표시한다.

```text
해당 계정의 자료는 A계정으로 통합되었습니다.
A계정으로 로그인하시기 바랍니다.
(등록문서 0건, 공유문서 0건)
```

## 보안 기준

- Client Secret은 서버에서만 사용한다.
- OAuth `state` 값을 사용하여 CSRF를 방지한다.
- Redirect URI는 제공자 콘솔에 등록된 값과 정확히 일치시킨다.
- 로그에 토큰, Client Secret, Authorization Code를 남기지 않는다.
- 비밀번호는 원문 저장을 금지하고 단방향 해시로 저장한다.
- 비밀번호 해시 알고리즘은 Argon2id를 1순위로 검토한다.
- Node.js 또는 배포 환경 제약으로 Argon2id 운영이 어렵다면 bcrypt를 2순위로 검토한다.
- OAuth Access Token과 Refresh Token은 MVP1에서 저장하지 않는 방향을 우선한다.
- 장기 API 호출 때문에 OAuth 토큰 저장이 필요해지면 암호화 저장, 키 식별자, 키 회전 정책을 별도 설계한다.

## 테스트 시나리오

| 시나리오 | 기대 결과 |
| :--- | :--- |
| 신규 카카오/네이버/구글 로그인 | 신규 User와 AuthIdentity 생성 |
| 기존 카카오/네이버/구글 로그인 | 기존 User로 로그인 |
| 로그인 상태에서 미연결 구글 연결 | 현재 User에 Google AuthIdentity 연결 |
| 로그인 상태에서 다른 계정의 카카오 연결 시도 | `ACCOUNT_MERGE_REQUIRED` 반환 |
| 대상 계정의 계정 통합 승인 | 대표 User로 데이터 이전, 보조 User는 `merged` |
| 이메일 동일 계정 발견 | 자동 통합하지 않음 |
| 간편로그인 전체 해제 | ID/PW 기본 로그인은 유지되고 간편로그인은 모두 해제 |
| ID/PW 삭제 시도 | 삭제 차단, 탈퇴 절차 안내 |
| 이메일 인증 필수 상태에서 인증 이메일 삭제 | 삭제 차단 |
| 이메일 변경 | 새 이메일 인증 완료 후 이메일 정보 교체 |
| 이메일 인증 필수 정책에서 미인증 사용자 로그인 | 로그인 허용 후 사용자정보 수정 화면으로 이동, 이메일 인증 안내 표시 |
| 이메일 인증번호 재발송 | 기존 미완료 인증번호 폐기 후 새 인증번호 발급 |
