# 03. 도메인 설계

## 목적

PDFrend의 핵심 도메인과 인증/계정 통합 모델을 정의한다. 본 문서는 정책과 기획 요구사항을 구현 가능한 설계 단위로 변환한다.

## 도메인 목록

| 도메인 | 책임 |
| :--- | :--- |
| User | 회원, 프로필, 로그인 수단, 계정 통합 |
| Document | 문서 생명주기, 메타데이터, 상태 |
| Version | 버전 생성, 체크포인트, 변경 추적 |
| Annotation | 주석 CRUD, 작성자, 검색, 상태 |
| Sharing | 공유 대상, 권한, 만료 |
| Sync | 실시간 동기화, 오프라인 변경, 충돌 해결 |
| Storage | 원본 PDF, 페이지 이미지, OCR, 병합 파일 저장 |
| Audit | 로그인, 연결, 통합, 문서 변경 감사 로그 |

## User 도메인 모델

### User

내부 회원계정이다. 외부 로그인 계정과 독립적으로 존재한다.

| 속성 | 설명 |
| :--- | :--- |
| `id` | 내부 회원 식별자. UUID 사용 후보 |
| `display_name` | 서비스 표시명 |
| `primary_email` | 알림 또는 표시용 이메일 |
| `status` | `active`, `merged`, `suspended`, `deleted` |
| `merged_into_user_id` | 병합된 경우 대표 회원 ID |
| `created_at` | 생성 일시 |
| `updated_at` | 수정 일시 |

### AuthIdentity

회원에 연결된 로그인 수단이다.

| 속성 | 설명 |
| :--- | :--- |
| `id` | 인증수단 식별자 |
| `user_id` | 연결된 내부 회원 ID |
| `provider` | `local`, `kakao`, `naver`, `google` |
| `provider_user_id` | 제공자 내부 사용자 식별자 |
| `email_from_provider` | 제공자가 반환한 이메일. 통합 판단의 단독 근거로 사용하지 않음 |
| `connected_at` | 연결 일시 |
| `last_login_at` | 마지막 로그인 일시 |

### 제약조건

- `(provider, provider_user_id)`는 전역 유니크다.
- 하나의 `user_id`는 여러 `AuthIdentity`를 가질 수 있다.
- 하나의 `AuthIdentity`는 하나의 `user_id`에만 연결된다.
- 마지막 남은 로그인 수단은 해제할 수 없다.

## 계정 연결 흐름

```text
로그인 사용자
  -> 간편로그인 연결 요청
  -> OAuth 인증 완료
  -> provider_user_id 조회
  -> 연결 이력 없음: 현재 user_id에 연결
  -> 다른 user_id에 연결됨: ACCOUNT_MERGE_REQUIRED 반환
```

## 계정 통합 흐름

```text
A01 로그인 상태
  -> kakao01 연결 시도
  -> kakao01이 A02에 연결되어 있음
  -> A01 사용자에게 통합 안내
  -> 사용자 동의
  -> 대표 계정 결정
  -> AuthIdentity, 문서, 주석, 공유 권한, 설정 이전
  -> 보조 계정 merged 처리
  -> Audit 로그 기록
```

## 병합 시 데이터 처리 원칙

| 데이터 | 처리 원칙 |
| :--- | :--- |
| AuthIdentity | 대표 계정으로 이전 |
| Document | 소유자 ID를 대표 계정으로 이전 |
| Annotation | 작성자 ID를 대표 계정으로 이전하되 감사 로그에 원 계정 기록 |
| Sharing | 대표 계정 기준으로 권한 재연결 |
| User Settings | 충돌 항목은 대표 계정 설정 우선 |
| Audit | 기존 로그는 보존하고 병합 이벤트를 추가 |

## 오류 상태

| 코드 | 의미 |
| :--- | :--- |
| `AUTH_IDENTITY_ALREADY_LINKED` | 로그인 수단이 이미 현재 계정에 연결되어 있음 |
| `ACCOUNT_MERGE_REQUIRED` | 로그인 수단이 다른 내부 계정에 연결되어 있음 |
| `LAST_AUTH_IDENTITY_REQUIRED` | 마지막 로그인 수단 해제 불가 |
| `ACCOUNT_MERGE_CONFLICT` | 병합 대상 데이터 충돌 |

## 설계 주의사항

- 이메일, 이름, 전화번호는 계정 자동 통합의 근거로 사용하지 않는다.
- 본인인증을 제외했으므로 통합은 법적 동일인 보장이 아니라 접근권 확인 기반 통합이다.
- 계정 통합은 트랜잭션으로 처리해야 한다.
- 통합 전후에는 감사 로그를 남긴다.
