# 03. 도메인 설계

## 목적

PDFowers의 핵심 도메인과 인증/계정 통합 모델을 정의한다. 본 문서는 정책과 기획 요구사항을 구현 가능한 설계 단위로 변환한다.

## 도메인 목록

| 도메인 | 책임 |
| :--- | :--- |
| User | 회원 내부 식별자, 프로필, ID/이메일 로그인 수단, 계정 통합 |
| Document | 문서 생명주기, 메타데이터, 상태 |
| Version | 버전 생성, 체크포인트, 변경 추적 |
| Annotation | 주석 CRUD, 작성자, 검색, 상태 |
| Sharing | 공유 대상, 권한, 만료 |
| Sync | 실시간 동기화, 오프라인 변경, 충돌 해결 |
| Storage | 원본 PDF, 페이지 이미지, OCR, 병합 파일 저장 |
| Audit | 로그인, 연결, 통합, 문서 변경 감사 로그 |

## User 도메인 모델

### User

내부 회원계정이다. 외부 로그인 계정과 독립적으로 존재한다.

| 속성 | 설명 |
| :--- | :--- |
| `user_uuid` | 사용자가 알 수 없는 내부 회원 식별자. UUID 타입 후보 |
| `display_name` | 서비스 표시명 |
| `primary_email` | 알림 또는 표시용 이메일 |
| `user_status_cd` | `ACTIVE`, `MERGED`, `SUSPENDED`, `DELETED` |
| `merged_into_user_uuid` | 병합된 경우 대표 회원 내부 식별자 |
| `created_at` | 생성 일시 |
| `updated_at` | 수정 일시 |
| `version` | 변경 충돌 감지를 위한 버전 |

### AuthIdentity

회원에 연결된 로그인 수단이다.

| 속성 | 설명 |
| :--- | :--- |
| `auth_identity_uuid` | 인증수단 식별자 |
| `user_uuid` | 연결된 내부 회원 식별자 |
| `provider_cd` | `LOCAL`, `KAKAO`, `NAVER`, `GOOGLE` |
| `provider_user_id` | 제공자 내부 사용자 식별자 |
| `email_from_provider` | 제공자가 반환한 이메일. 계정 조회 후보로 사용할 수 있으나 자동 통합 단독 근거로 사용하지 않음 |
| `connected_at` | 연결 일시 |
| `last_login_at` | 마지막 로그인 일시 |
| `version` | 변경 충돌 감지를 위한 버전 |

### LocalCredential

ID/PW 기본 로그인을 위한 내부 자격 증명이다. 비밀번호 원문은 저장하지 않는다. 기본 로그인 정보는 사용자가 임의 삭제할 수 없고, 계정 삭제는 탈퇴 절차로 처리한다.

| 속성 | 설명 |
| :--- | :--- |
| `user_uuid` | 연결된 내부 회원 식별자 |
| `login_id` | 서비스 로그인용 ID |
| `password_hash` | 안전한 해시 알고리즘으로 저장한 비밀번호 |
| `password_hash_alg_cd` | 비밀번호 해시 알고리즘 코드 |
| `updated_at` | 수정 일시 |
| `version` | 변경 충돌 감지를 위한 버전 |

### VerifiedEmail

이메일 로그인, 이메일 인증, 작업 알림 수신 대상을 관리한다.

| 속성 | 설명 |
| :--- | :--- |
| `verified_email_uuid` | 이메일 식별자 |
| `user_uuid` | 연결된 내부 회원 식별자 |
| `email` | 로그인 또는 알림 대상 이메일 |
| `email_verified_at` | 이메일 인증 완료 일시 |
| `email_notification_opt_in` | 이메일 작업 알림 수신 동의 여부 |
| `updated_at` | 수정 일시 |
| `version` | 변경 충돌 감지를 위한 버전 |

### 제약조건

- `(provider_cd, provider_user_id)`는 전역 유니크다.
- `login_id`와 인증 이메일은 각각 유니크 제약 후보로 둔다.
- 하나의 `user_uuid`는 여러 `AuthIdentity`를 가질 수 있다.
- 하나의 `AuthIdentity`는 하나의 `user_uuid`에만 연결된다.
- ID/PW 기본 로그인 정보는 임의 삭제할 수 없다.
- 카카오, 네이버, 구글 간편로그인은 모두 해제할 수 있다.
- 이메일 인증 필수 설정에서는 인증 완료 이메일 삭제를 차단한다.
- 이메일 변경은 새 이메일 인증 완료 후 반영한다.

### AccountMergeRequest

계정 통합 요청의 상태를 관리한다. 다른 계정에 연결된 간편로그인을 현재 계정에 연결하려 할 때 생성된다.

| 속성 | 설명 |
| :--- | :--- |
| `merge_request_uuid` | 계정 통합 요청 식별자 |
| `request_user_uuid` | 연결을 요청한 대표 계정 후보 |
| `target_user_uuid` | 기존 간편로그인을 보유한 대상 계정 |
| `provider_cd` | 계정 통합 대상 간편로그인 제공자 |
| `provider_user_id` | 제공자 내부 사용자 식별자 |
| `merge_status_cd` | `PENDING`, `APPROVED`, `CANCELLED`, `EXPIRED` |
| `expires_at` | 승인 가능 만료 일시 |
| `approved_at` | 승인 일시 |
| `cancelled_at` | 취소 일시 |

계정 통합 요청은 `PENDING` 상태에서만 승인 또는 취소할 수 있다. 만료된 요청은 승인 시점에 `EXPIRED`로 전환하고, AuthIdentity와 User 상태를 변경하지 않는다. 이미 승인된 요청의 중복 승인은 오류로 처리한다.

### AuditLog

인증과 계정 통합의 보안 이벤트를 기록한다. 현재 도메인 테스트는 다음 이벤트 생성을 확인한다.

| 이벤트 | 발생 조건 |
| :--- | :--- |
| `LOCAL_USER_CREATED` | 로컬 계정 생성 |
| `LOGIN_SUCCESS` | 로컬 또는 간편로그인 성공 |
| `LOGIN_FAILURE` | 로컬 로그인 실패 |
| `EMAIL_VERIFICATION_REQUIRED` | 이메일 인증 필수 설정에서 미인증 로그인 차단 |
| `AUTH_IDENTITY_LINKED` | 간편로그인 연결 |
| `AUTH_IDENTITY_UNLINKED` | 간편로그인 해제 |
| `ACCOUNT_MERGE_REQUESTED` | 다른 계정의 간편로그인 연결 시도 |
| `ACCOUNT_MERGE_APPROVED` | 계정 통합 승인 |
| `ACCOUNT_MERGE_CANCELLED` | 계정 통합 요청 취소 |
| `ACCOUNT_MERGE_EXPIRED` | 계정 통합 요청 만료 |

## 계정 연결 흐름

```text
로그인 사용자
  -> 간편로그인 연결 요청
  -> OAuth 인증 완료
  -> provider_user_id 조회
  -> 연결 이력 없음: 현재 user_uuid에 연결
  -> 다른 user_uuid에 연결됨: ACCOUNT_MERGE_REQUIRED 반환 및 대상 계정에 병합 요청
```

## 계정 통합 흐름

```text
A01 로그인 상태
  -> kakao01 연결 시도
  -> kakao01이 A02에 연결되어 있음
  -> A01 사용자에게 대상 계정 승인 필요 안내
  -> A02 계정으로 로그인
  -> A02 사용자에게 통합되는 정보 확인 및 동의 여부 안내
  -> A02 사용자가 통합 승인
  -> 대표 계정 결정
  -> AuthIdentity, 문서, 주석, 공유 권한, 설정 이전
  -> 보조 계정 merged 처리
  -> Audit 로그 기록
```

## 병합 시 데이터 처리 원칙

| 데이터 | 처리 원칙 |
| :--- | :--- |
| AuthIdentity | 대표 계정으로 이전 |
| Document | 소유자 내부 식별자를 대표 계정으로 이전 |
| Annotation | 작성자 내부 식별자를 대표 계정으로 이전하되 감사 로그에 원 계정 기록 |
| Sharing | 대표 계정 기준으로 권한 재연결 |
| User Settings | 충돌 항목은 대표 계정 설정 우선 |
| Audit | 기존 로그는 보존하고 병합 이벤트를 추가 |

## 오류 상태

| 코드 | 의미 |
| :--- | :--- |
| `AUTH_IDENTITY_ALREADY_LINKED` | 로그인 수단이 이미 현재 계정에 연결되어 있음 |
| `ACCOUNT_MERGE_REQUIRED` | 로그인 수단이 다른 내부 계정에 연결되어 있음 |
| `LOCAL_CREDENTIAL_REQUIRED` | 기본 ID/PW 로그인 정보 삭제 불가 |
| `EMAIL_VERIFICATION_REQUIRED` | 이메일 인증 필수 설정에서 미인증 로그인 차단 |
| `VERIFIED_EMAIL_REQUIRED` | 이메일 인증 필수 설정에서 인증 완료 이메일 삭제 불가 |
| `AUTH_IDENTITY_NOT_LINKED` | 해제하려는 간편로그인이 연결되어 있지 않음 |
| `MERGE_REQUEST_EXPIRED` | 계정 통합 요청이 만료됨 |
| `MERGE_REQUEST_CANCELLED` | 취소된 계정 통합 요청 승인 시도 |
| `MERGE_REQUEST_NOT_PENDING` | 대기 상태가 아닌 계정 통합 요청 변경 시도 |
| `DUPLICATE_MERGE_APPROVAL` | 이미 승인된 계정 통합 요청의 중복 승인 |

## 설계 주의사항

- 이메일은 계정 조회와 식별 후보로 사용할 수 있으나, 이메일 동일성만으로 계정을 자동 통합하지 않는다.
- 본인인증을 제외했으므로 통합은 법적 동일인 보장이 아니라 접근권 확인 기반 통합이다.
- 계정 통합은 트랜잭션으로 처리해야 한다.
- 통합 전후에는 감사 로그를 남긴다.
