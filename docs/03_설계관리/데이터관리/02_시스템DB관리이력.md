# 02. 시스템 DB 관리이력

## 목적

PDFowers 시스템 DB의 구조 변경과 서비스 초기데이터 변경 이력을 추적한다. 본 문서는 이후 신규 시스템 또는 새 환경의 초기 DB를 구축할 때 기준 이력으로 사용한다.

## 관리 범위

| 구분 | 관리 대상 | 예시 | 관리 여부 |
| :--- | :--- | :--- | :---: |
| DB 구조 | 테이블 등록, 수정, 삭제 | `user_account` 생성, 컬럼 추가, 인덱스 삭제 | 관리 |
| DB 제약 | PK, FK, unique index, extension | `auth_identity(provider_cd, provider_user_id)` unique | 관리 |
| 서비스 데이터 | 공통코드, 시스템 설정, 기본 정책값 | `USER_STATUS`, `AUTH_PROVIDER`, `MERGE_STATUS` | 관리 |
| 활동 데이터 | 사용자의 서비스 이용 과정에서 발생한 데이터 | 회원정보, 문서정보, 주석, 감사 이벤트 개별 row | 제외 |

회원정보, 문서정보, 주석, 실제 감사 로그 row는 서비스 활동 데이터이므로 본 관리이력의 초기데이터 대상에 포함하지 않는다. 단, 해당 데이터를 담는 테이블 구조와 공통코드 값은 관리 대상이다.

## 이력 작성 규칙

1. 테이블 변경은 등록, 수정, 삭제를 구분해 기록한다.
2. 서비스 데이터 변경은 등록, 수정, 삭제를 구분하고, 재구축 가능한 코드값과 라벨을 남긴다.
3. 민감정보, DB 비밀번호, 실제 사용자 개인정보, OAuth 토큰 원문은 기록하지 않는다.
4. 실제 migration 파일이 있으면 `근거 파일`에 연결한다.
5. 활동 데이터는 “관리 제외”로 판단 근거만 기록하고 row 값은 남기지 않는다.

## 초기 DB 재구축 사용 기준

새 환경의 초기 DB는 다음 순서로 구성한다.

1. PostgreSQL 기본 확장과 DB 서버 설정을 적용한다.
2. migration 파일 순서대로 테이블과 제약을 생성한다.
3. `0001_gray_joseph.sql` migration으로 `src/db/seed/common-codes.ts` 기준 공통코드를 `common_code`에 등록한다.
4. 회원정보, 문서정보, 감사 로그, Job 실행 row는 마이그레이션 또는 seed 대상에서 제외한다.
5. 환경별 비밀번호와 접속 URL은 `.env` 또는 시크릿 저장소에서 주입한다.
