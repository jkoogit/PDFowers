# 03. 하네스 세션·태스크·루프 진행관리 문서 DB 설계서

## 1. 개요 및 설계 원칙

본 문서는 PDFowers 프로젝트의 AI 에이전트 하네스 3계층(**세션 - 태스크 - 루프**)의 진행 정보와 작업 그래프, 백로그, 회고, 마크다운 문서 메타데이터를 체계적이고 유연하게 관리하기 위한 **문서 DB(Document Store / JSON Document) 및 영속화 스키마**를 정의한다.

### 1.1 설계 원칙
1. **문서 우선 및 단일 진실 공급원 (Markdown & Code First SSOT)**:
   - 물리적 마크다운 문서(`/docs/*.md`)와 Git 소스 코드가 절대적인 원천(Source of Truth)이다.
   - DB는 검색 가속, 대시보드 뷰어 렌더링, 작업 진행도 추적, API 연계를 위한 **"읽기 최적화 프로젝션(Read-Model)"**으로 동작한다.
2. **문서 DB(Document Store)의 유연성 확보**:
   - 세션/태스크/루프의 메트릭, AI 메타, 작업 그래프, diff 요약 등 진화가 빠른 비정형 데이터는 **JSON Document Schema**로 유연하게 수용한다.
   - 검색 빈도가 높고 관계 무결성이 필요한 핵심 키(ID, 상태, 일시, 버전)는 관계형 인덱스/메타 테이블로 함께 관리한다.
3. **낙관적 잠금 (Optimistic Locking)**:
   - 모든 엔티티에 `version` 정수 필드를 두어 동시 수정 충돌 및 경합을 방지한다.
4. **상시 자가 치유 (Reconciliation)**:
   - 상위 요약 정보와 하위 상세 정보 간의 상태 불일치가 감지되면 언제든 하위 문서를 기준으로 상위를 자동 보정하는 Reconciler 메커니즘을 지원한다.

## 8. 관계형 인덱스 테이블 DDL (PostgreSQL / Drizzle 기준)

문서 DB의 빠른 검색 및 상위 무결성 보장을 위해 메타/인덱스 RDB 테이블을 병행 구성한다.

```sql
-- 1. 세션 인덱스 테이블
CREATE TABLE harness_session_meta (
    session_id VARCHAR(64) PRIMARY KEY,
    session_name VARCHAR(255) NOT NULL,
    work_group VARCHAR(100) NOT NULL,
    status_cd VARCHAR(30) NOT NULL,
```

## 9. 자가 치유(Reconciler) 및 정합성 검증 흐름

1. **상시 Reconcile 실행 (`reconcileSession(sessionId)`)**:
   - `harness_task_meta`에서 해당 세션의 모든 태스크를 조회.
   - 세션 문서의 `task_list` 배열과 실제 태스크 목록 및 상태를 비교.
   - 불일치가 있을 경우 하위 태스크 실제 레코드를 기준으로 상위 세션 문서의 `task_list`를 덮어쓰고 `version = version + 1` 갱신.
2. **루프 가드 (Loop Guard 검증)**:
   - 태스크 종료/정리 시점에 해당 태스크에 속한 모든 루프의 `status_cd`가 `정리(COMPLETED)` 또는 `정지(ABORTED)`인지 검사.
   - 미완료 루프가 존재할 경우 태스크 정리 거부(Exception).
3. **문서 동기화 및 크로스체크 (`verifyDocsConsistency()`)**:
   - 로컬 `/docs` 디렉토리의 모든 `.md` 파일의 SHA-256 해시를 계산.
   - DB `agent_docs_meta`의 `content_hash`와 대조하여 누락 또는 변경된 파일을 즉시 파싱 및 동기화.

### 10.2 세션 - 태스크 - 루프 3계층 통합 계층 조회 (Hierarchical JOIN)
세션의 진행 상황과 하위 태스크, 루프 목록 및 소요시간, 상태를 트리 구조로 조회합니다.
```sql
SELECT 
    s.session_id,
    s.session_name,
    s.status_cd AS session_status,
    s.ai_agent,
    s.ai_model,
    t.task_id,
    t.task_name,
    t.status_cd AS task_status,
    t.git_branch,
    l.loop_id,
    l.loop_name,
    l.status_cd AS loop_status,
    l.started_at AS loop_started_at,
    l.ended_at AS loop_ended_at,
    ROUND(EXTRACT(EPOCH FROM (COALESCE(l.ended_at, NOW()) - l.started_at))::numeric, 1) AS loop_duration_seconds
FROM harness_session_meta s
LEFT JOIN harness_task_meta t ON s.session_id = t.session_id
LEFT JOIN harness_loop_meta l ON t.task_id = l.task_id
ORDER BY s.started_at DESC, t.started_at ASC, l.started_at ASC;
```

### 10.3 JSONB 내부 문서 필드 심층 추출 쿼리 (PostgreSQL JSONB 연산자)
JSON 문서 내부에 보관된 PR 정보, 토큰 소비량, 회고 요약 등을 관계형 컬럼처럼 추출합니다.

```sql
-- 1) 세션별 누적 토큰 사용량 및 회고 요약 추출
SELECT 
    session_id,
    session_name,
    status_cd,
    doc_payload->'aiMeta'->'totalTokenUsage'->>'promptTokens' AS prompt_tokens,
    doc_payload->'aiMeta'->'totalTokenUsage'->>'completionTokens' AS completion_tokens,
    doc_payload->'aiMeta'->'totalTokenUsage'->>'totalTokens' AS total_tokens,
    doc_payload->'retrospective'->>'summary' AS retro_summary,
    doc_payload->'backlogIds' AS official_backlogs
FROM harness_session_meta
ORDER BY started_at DESC;

-- 2) 태스크별 Git PR 번호 및 PR URL 추출
SELECT 
    task_id,
    task_name,
    git_branch,
    status_cd,
    doc_payload->'gitInfo'->'pr'->>'prNumber' AS pr_number,
    doc_payload->'gitInfo'->'pr'->>'title' AS pr_title,
    doc_payload->'gitInfo'->'pr'->>'url' AS pr_url,
    doc_payload->'gitInfo'->>'endCommit' AS end_commit
FROM harness_task_meta
WHERE doc_payload->'gitInfo'->'pr' IS NOT NULL;

-- 3) 루프별 단위 검증 명령어 및 diff 요약 통계 추출
SELECT 
    loop_id,
    loop_name,
    status_cd,
    doc_payload->'workItem'->>'verifyCommand' AS verify_command,
    doc_payload->'diffSummary' AS diff_summary,
    doc_payload->'verifyResult'->>'status' AS verify_status,
    doc_payload->'verifyResult'->>'logs' AS verify_logs
FROM harness_loop_meta;
```

### 10.5 대화 감사 로그 타임라인 및 모델별 토큰 사용량 통계
```sql
-- 1) 특정 세션의 대화 턴(Step)별 대화 감사 타임라인
SELECT 
    step_index,
    agent_name,
    model_name,
    user_prompt,
    SUBSTRING(agent_response FROM 1 FOR 100) AS response_preview,
    prompt_tokens,
    completion_tokens,
    total_tokens,
    created_at
FROM agent_conversation_trace
WHERE session_id = 'SES-20260915-01' -- 조회할 세션 ID
ORDER BY step_index ASC;

-- 2) 에이전트/모델별 누적 토큰 소비 및 대화 턴 수 집계
SELECT 
    agent_name,
    model_name,
    COUNT(*) AS total_turns,
    SUM(prompt_tokens) AS sum_prompt_tokens,
    SUM(completion_tokens) AS sum_completion_tokens,
    SUM(total_tokens) AS grand_total_tokens,
    ROUND(AVG(total_tokens)::numeric, 1) AS avg_tokens_per_turn
FROM agent_conversation_trace
GROUP BY agent_name, model_name
ORDER BY grand_total_tokens DESC;
```

### 10.6 루프 가드(Loop Guard) 정합성 이상 감지 쿼리
태스크 상태가 '정리' 또는 '승급'인데 하위에 아직 완료되지 않은 루프('분석', '처리', '보완')가 남아있는 이상 데이터를 탐지합니다.
```sql
SELECT 
    t.task_id,
    t.task_name,
    t.status_cd AS task_status,
    l.loop_id,
    l.loop_name,
    l.status_cd AS loop_status
FROM harness_task_meta t
JOIN harness_loop_meta l ON t.task_id = l.task_id
WHERE t.status_cd IN ('정리', '승급', '완료')
  AND l.status_cd NOT IN ('정리', '정지', '폐기');
```

### 10.7 데이터베이스 누락 주석 탐색 및 자동 보완 스크립트

신규 테이블이나 컬럼 추가 시 PostgreSQL 카탈로그(`pg_description`) 상의 한글 주석 누락 여부를 상시 점검하고 자동으로 보완하는 쿼리 및 실행 스크립트입니다.

#### 1) 누락된 테이블/컬럼 주석 자동 탐색 쿼리
```sql
-- 1) 한글 주석이 누락된 테이블 목록 탐색
SELECT 
    t.table_schema,
    t.table_name,
    obj_description(c.oid, 'pg_class') AS table_comment
FROM information_schema.tables t
JOIN pg_class c ON c.relname = t.table_name
JOIN pg_namespace n ON n.oid = c.relnamespace AND n.nspname = t.table_schema
WHERE t.table_schema = 'public'
  AND t.table_type = 'BASE TABLE'
  AND (obj_description(c.oid, 'pg_class') IS NULL OR obj_description(c.oid, 'pg_class') = '');

-- 2) 한글 주석이 누락된 컬럼 목록 탐색
SELECT 
    c.table_name,
    c.column_name,
    c.data_type,
    col_description(cl.oid, c.ordinal_position) AS column_comment
FROM information_schema.columns c
JOIN pg_class cl ON cl.relname = c.table_name
JOIN pg_namespace n ON n.oid = cl.relnamespace AND n.nspname = c.table_schema
WHERE c.table_schema = 'public'
  AND (col_description(cl.oid, c.ordinal_position) IS NULL OR col_description(cl.oid, c.ordinal_position) = '')
ORDER BY c.table_name, c.ordinal_position;
```

#### 2) 주석 일괄 적용 및 보완 실행 스크립트
- **실행 명령**: `npm run db:comments` (또는 `npx tsx src/db/scripts/apply-comments.ts`)
- **DDL 정의 파일**: [`src/db/sql/table_column_comments.sql`](file:///d:/dev/workspace/git.jkoogit/PDFowers/src/db/sql/table_column_comments.sql)
- **주석 현황 요약 확인**:
```sql
SELECT 
  (SELECT COUNT(*) FROM pg_class c JOIN pg_namespace n ON n.oid = c.relnamespace 
   WHERE n.nspname = 'public' AND c.relkind = 'r' AND obj_description(c.oid, 'pg_class') IS NOT NULL) AS table_comment_count,
  (SELECT COUNT(*) FROM pg_description d JOIN pg_class c ON c.oid = d.objoid JOIN pg_namespace n ON n.oid = c.relnamespace 
   WHERE n.nspname = 'public' AND c.relkind = 'r' AND d.objsubid > 0) AS column_comment_count;
```
