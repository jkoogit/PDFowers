# 07. 일정관리

## 목적

신규 프로젝트의 로드맵, 마일스톤, 스프린트, 일정 변경을 관리한다.

## 기존 참고 문서에서 유지할 핵심

기존 로드맵은 단계별 개발을 지향했다.

| 단계 후보 | 핵심 산출물 |
| :--- | :--- |
| Phase 0 | 문서 체계, 기술 결정, 개발 환경 |
| Phase 1 | 인증, DB 스키마, 업로드/다운로드 API |
| Phase 2 | PDF 뷰어 MVP, 주석 CRUD, 대시보드 |
| Phase 3 | 실시간 동기화, 오프라인, 공유 |
| Phase 4 | PWA, 관리자, OCR, 성능 튜닝, 운영 안정화 |

신규 프로젝트에서는 과거 일정과 완료 상태를 승계하지 않는다. 2026-06-07 이후 하네스 기반 프로젝트 착수일을 기준으로 다시 산정한다.

## 권장 초기 로드맵

| 단계 | 목표 |
| :--- | :--- |
| Phase 0 | 하네스 프로젝트 생성, 문서 체계 확정, 기술 스택 재승인 |
| Phase 1 | 문서 업로드/다운로드 파이프라인 PoC |
| Phase 2 | PDF 뷰어 MVP와 기본 문서 관리 |
| Phase 3 | 주석, 버전, 권한 모델 구현 |
| Phase 4 | 오프라인/실시간 동기화와 운영 안정화 |

## 초기화 기준

기존 이슈 #1~#5 상태, 과거 커밋, 완료 문구는 일정 근거로 사용하지 않는다. 필요한 경우 `참고 이력`으로만 별도 표기한다.

## 검토 필요사항

- MVP를 파일 파이프라인 중심으로 할지, 뷰어 중심으로 할지 결정해야 한다.
- 인증 구현을 초기에 포함할지, 로컬 개발용 임시 사용자로 분리할지 결정해야 한다.
- 하네스 기반 개발 속도를 확인하기 전까지 월 단위 일정은 확정하지 않는다.
