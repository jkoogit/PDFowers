# 01. MVP 검증 계획

## 목적

1차 MVP의 완료 조건과 검증 게이트를 정의한다. 1차 MVP는 인증, 간편로그인, 로그인 수단 연결, 계정 통합을 대상으로 하며 PDF 업로드, 주석, 공유, 동기화는 후속 MVP 검증 범위로 분리한다.

## 검증 범위

| 구분 | 포함 여부 | 내용 |
| :--- | :---: | :--- |
| ID 기반 회원가입 | 포함 | `login_id`, 이메일, 비밀번호, 표시명 기반 계정 생성 |
| 기본 로그인 | 포함 | ID/PW를 기본 로그인 수단으로 사용하며 사용자가 임의 삭제할 수 없음 |
| 이메일 로그인 | 포함 | 설정에 따라 이메일 인증 후 로그인 수단으로 사용 |
| 이메일 인증 | 포함 | 필수/선택 설정에 따른 로그인 허용 조건 검증 |
| 간편로그인 | 포함 | 카카오, 네이버, 구글 선택 로그인과 연결/해제 검증 |
| 로그인 수단 연결 | 포함 | 로그인 상태에서 미연결 OAuth 제공자 연결, 간편로그인 해제 |
| 계정 통합 | 포함 | 다른 계정에 연결된 OAuth 식별자 연결 시 승인 기반 통합 |
| 감사 로그 | 포함 | 로그인, 인증수단 연결, 계정 통합 이벤트 기록 |
| 실제 이메일 발송 | 조건부 | MVP1 초기에는 모의 발송 또는 이벤트 저장으로 검증 가능 |
| PDF 업로드/주석/공유/동기화 | 제외 | 2차 이후 MVP 검증 범위 |

## 완료 조건

| ID | 완료 조건 | 확인 방법 |
| :--- | :--- | :--- |
| `MVP1-DONE-001` | ID/이메일 회원가입과 로그인이 정상 동작한다. | 단위/통합 테스트 |
| `MVP1-DONE-002` | 비밀번호 원문과 OAuth 토큰이 저장소와 로그에 남지 않는다. | 코드 리뷰, 로그 확인 |
| `MVP1-DONE-003` | 이메일 인증 필수/선택 설정에 따라 로그인 허용 조건이 달라진다. | 통합 테스트 |
| `MVP1-DONE-004` | 신규 OAuth 사용자는 회원가입 흐름으로 이동하고, 기존 OAuth 사용자는 기존 계정으로 로그인한다. | 통합 테스트 |
| `MVP1-DONE-005` | 로그인 상태에서 미연결 OAuth 제공자를 현재 계정에 연결할 수 있다. | 통합 테스트 |
| `MVP1-DONE-006` | 다른 계정에 연결된 OAuth 제공자 연결 시 자동 통합하지 않고 계정 통합 요청을 만든다. | 통합 테스트 |
| `MVP1-DONE-007` | 계정 통합 승인 시 AuthIdentity가 대표 계정으로 이전되고 보조 계정은 `merged` 상태가 된다. | 통합 테스트, DB 확인 |
| `MVP1-DONE-008` | 이메일 동일성만으로 계정을 자동 통합하지 않는다. | 통합 테스트 |
| `MVP1-DONE-009` | ID/PW 기본 로그인 정보는 삭제할 수 없고, 간편로그인은 모두 해제할 수 있다. | 단위/통합 테스트 |
| `MVP1-DONE-010` | 주요 인증 이벤트가 AuditLog에 기록된다. | 통합 테스트, DB 확인 |
| `MVP1-DONE-011` | 이메일 인증 필수 설정에서는 인증 완료 이메일 삭제가 차단되고, 이메일 변경은 새 이메일 인증 완료 후 반영된다. | 통합 테스트 |

## 테스트 계층

| 계층 | 대상 | 기준 |
| :--- | :--- | :--- |
| 단위 테스트 | 비밀번호 검증, 이메일 인증 정책, 계정 통합 상태 전이, 인증 수단 삭제 정책 | 외부 DB/OAuth 없이 순수 로직 검증 |
| 통합 테스트 | 회원가입, 로그인, OAuth 콜백 처리, AuthIdentity 연결, 계정 통합 승인 | 테스트 DB와 모의 OAuth 제공자 사용 |
| E2E 테스트 | 가입, 로그인, 로그인 수단 연결, 계정 통합 안내 화면 | 하네스 UI가 생성된 뒤 최소 성공 경로 검증 |

## 품질 게이트

| 게이트 | 기준 |
| :--- | :--- |
| 문서 게이트 | 요구사항 ID와 테스트 ID가 매핑되어야 한다. |
| 보안 게이트 | 비밀번호 원문, OAuth 토큰, Client Secret, Authorization Code가 로그에 남지 않아야 한다. |
| 데이터 게이트 | `AuthIdentity(provider, provider_user_id)` 유니크 제약이 있어야 한다. |
| 회귀 게이트 | 기존 로그인 수단 연결 후에도 기존 로그인 경로가 유지되어야 한다. |
| 운영 게이트 | 로컬/테스트/운영 OAuth 앱과 환경변수 분리 기준이 문서화되어야 한다. |

## 결정 대기 항목

| ID | 항목 | 임시 검증 기준 |
| :--- | :--- | :--- |
| `MVP1-VERIFY-WAIT-001` | 이메일 인증 필수 여부 | 테스트는 필수/선택 두 모드를 모두 작성하고 운영 기본값은 결정 후 고정한다. |
| `MVP1-VERIFY-WAIT-002` | 세션/JWT 방식 | 하네스 기본값 확인 전에는 인증 상태 저장소를 추상화한 테스트를 우선 작성한다. |
| `MVP1-VERIFY-WAIT-003` | 실제 이메일 발송 | 초기 검증은 알림 이벤트 저장 또는 모의 발송 성공으로 대체한다. |

## 시나리오 검증 프로세스

| 흐름 | 단계 | 검증 포인트 |
| :--- | :--- | :--- |
| 로그인 화면 | ID/PW, 이메일, 카카오, 네이버, 구글 선택지를 표시한다. | 각 선택지가 독립 진입점으로 동작해야 한다. |
| 미등록 ID/PW 로그인 | 존재하지 않는 `login_id`로 로그인을 시도한다. | 회원가입 화면으로 이동하거나 가입 안내 상태를 반환한다. |
| 미등록 이메일 로그인 | 등록되지 않은 이메일로 로그인을 시도한다. | 이메일 회원가입 화면 또는 가입 안내로 이동한다. |
| 미등록 간편로그인 | 제공자 인증은 성공했으나 AuthIdentity가 없다. | 회원가입 화면으로 이동하고 ID/PW, 표시명 입력 후 해당 간편로그인을 선택 등록한다. |
| 회원가입 완료 | ID/PW, 표시명, 선택한 간편로그인을 등록한다. | User, LocalCredential, 선택 AuthIdentity가 생성된다. |
| 가입 후 로그인 | 가입한 ID/PW 또는 연결된 간편로그인으로 로그인한다. | 로그인 성공 후 인증/계정 설정 화면으로 진입한다. |
| 이메일 인증 필수 | 이메일 미인증 계정이 로그인 또는 인증 화면에 접근한다. | 설정값에 따라 접근 차단 또는 인증 요청이 표시된다. |
| 간편로그인 이메일 | 간편로그인으로 가입/로그인한다. | 제공자 인증을 신뢰하므로 PDFowers 이메일 인증은 생략한다. |
| 간편로그인 해제 | 연결된 카카오/네이버/구글을 해제한다. | 기본 ID/PW가 유지되므로 모든 간편로그인은 해제 가능하다. |
| 인증 이메일 삭제 | 이메일 인증 필수 설정에서 인증 완료 이메일 삭제를 시도한다. | 삭제가 차단된다. 새 이메일 인증 완료 후 기존 이메일을 교체한다. |
