# 03. 인증 테스트

## 목적

1차 MVP 인증 범위의 테스트 케이스를 요구사항, 도메인, 구현 가이드와 연결한다. 본 문서는 하네스 테스트 스크립트 작성 전 기준 테스트 목록으로 사용한다.

## 테스트 데이터 원칙

- 테스트 계정의 이메일, 제공자 사용자 ID, 로그인 ID는 실제 개인정보를 사용하지 않는다.
- OAuth 제공자는 실제 외부 호출 대신 모의 제공자 응답으로 먼저 검증한다.
- 비밀번호 원문, OAuth 토큰, Authorization Code는 테스트 로그에 출력하지 않는다.
- 계정 통합 테스트는 요청 계정과 대상 계정을 명확히 분리한다.

## 테스트 케이스

| 테스트 ID | 요구사항 | 시나리오 | 기대 결과 |
| :--- | :--- | :--- | :--- |
| `MVP1-AUTH-T001` | `FR-AUTH-001`, `FR-AUTH-001-1` | 신규 사용자가 `login_id`, 이메일, 비밀번호, 표시명으로 가입한다. | User와 LocalCredential이 생성되고 비밀번호는 해시로 저장된다. |
| `MVP1-AUTH-T002` | `FR-AUTH-001-1` | 이메일 인증 필수 설정에서 미인증 사용자가 로그인한다. | 로그인 또는 주요 기능 접근이 차단되고 이메일 인증 안내가 반환된다. |
| `MVP1-AUTH-T003` | `FR-AUTH-001-1` | 이메일 인증 선택 설정에서 미인증 사용자가 로그인한다. | 설정값에 따라 로그인이 허용되며 인증 안내 상태가 유지된다. |
| `MVP1-AUTH-T004` | `FR-AUTH-001` | 사용자가 올바른 `login_id`와 비밀번호로 로그인한다. | 로그인 성공과 마지막 로그인 시각 갱신, AuditLog 기록이 발생한다. |
| `MVP1-AUTH-T005` | `FR-AUTH-001` | 사용자가 틀린 비밀번호로 로그인한다. | 로그인 실패가 반환되고 비밀번호 원문은 로그에 남지 않는다. |
| `MVP1-AUTH-T006` | `FR-AUTH-001`, `FR-AUTH-002` | 로그인 화면에서 미등록 카카오 사용자가 간편로그인을 선택한다. | 제공자 인증 후 회원가입 화면으로 이동하고 `login_id`, 비밀번호, 표시명 입력 후 Kakao AuthIdentity가 생성된다. |
| `MVP1-AUTH-T007` | `FR-AUTH-002` | 기존 카카오 AuthIdentity가 있는 사용자가 로그인한다. | 연결된 User로 로그인된다. |
| `MVP1-AUTH-T008` | `FR-AUTH-002` | 이미 존재하는 제공자 식별자로 회원가입을 시도한다. | 신규 가입이 차단되고 기존 로그인 안내가 반환된다. |
| `MVP1-AUTH-T009` | `FR-AUTH-003` | A01 로그인 상태에서 미연결 구글 계정을 연결한다. | A01에 Google AuthIdentity가 추가된다. |
| `MVP1-AUTH-T010` | `FR-AUTH-003` | A01 로그인 상태에서 이미 A01에 연결된 카카오 계정을 다시 연결한다. | `AUTH_IDENTITY_ALREADY_LINKED`가 반환된다. |
| `MVP1-AUTH-T011` | `FR-AUTH-003`, `FR-AUTH-004` | A01 로그인 상태에서 A02에 연결된 카카오 계정을 연결한다. | `ACCOUNT_MERGE_REQUIRED`가 반환되고 AccountMergeRequest가 생성된다. |
| `MVP1-AUTH-T012` | `FR-AUTH-004` | 대상 계정 A02 사용자가 계정 통합을 승인한다. | AuthIdentity가 대표 계정으로 이전되고 A02는 `merged` 상태가 된다. |
| `MVP1-AUTH-T013` | `FR-AUTH-004` | 계정 통합 승인 중 오류가 발생한다. | 트랜잭션이 롤백되고 AuthIdentity와 User 상태가 부분 변경되지 않는다. |
| `MVP1-AUTH-T014` | `FR-AUTH-004` | 이메일이 같은 두 계정이 존재한다. | 이메일 동일성만으로 자동 통합하지 않는다. |
| `MVP1-AUTH-T015` | 인증 구현 가이드 | 사용자가 연결된 카카오, 네이버, 구글 간편로그인을 모두 해제한다. | 모든 간편로그인이 해제되며 기본 ID/PW 로그인 정보는 유지된다. |
| `MVP1-AUTH-T016` | 보안 기준 | OAuth 콜백 처리 중 토큰 교환이 실패한다. | 인증 실패가 반환되고 토큰, 코드, Client Secret은 로그에 남지 않는다. |
| `MVP1-AUTH-T017` | 이메일 인증 정책 | 사용자가 기본 ID/PW 로그인 정보를 삭제하려 한다. | 삭제가 차단되며 계정 삭제는 탈퇴 절차로만 가능하다. |
| `MVP1-AUTH-T018` | 이메일 인증 정책 | 이메일 인증 필수 설정에서 인증 완료 이메일 삭제를 시도한다. | 삭제가 차단된다. |
| `MVP1-AUTH-T019` | 이메일 인증 정책 | 이메일 변경 시 새 이메일 인증을 완료한다. | 새 이메일이 인증 완료 상태로 반영되고 기존 이메일 정보가 교체된다. |
| `MVP1-AUTH-T020` | `FR-AUTH-002` | 간편로그인 사용자가 제공자 이메일을 받았으나 PDFowers 이메일 인증을 하지 않았다. | 간편로그인은 제공자 인증 결과로 로그인되며 PDFowers 이메일 인증은 생략된다. |
