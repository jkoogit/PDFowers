# 05. 테스트관리

## 목적

테스트 전략, 테스트 케이스, 검증 게이트, 테스트 결과를 관리한다.

## 기존 참고 문서에서 유지할 핵심

테스트는 단위 테스트, 통합 테스트, E2E 테스트로 계층화한다.

| 테스트 유형 | 비중 후보 | 목적 |
| :--- | :---: | :--- |
| 단위 테스트 | 60~70% | 도메인 로직, 값 객체, 순수 함수 검증 |
| 통합 테스트 | 20~30% | DB, API, 스토리지, 인증 흐름 검증 |
| E2E 테스트 | 5~10% | 사용자 여정과 브라우저 상호작용 검증 |

기능 검증은 위험도가 높은 흐름부터 진행한다.

1. 업로드, 리소스 분리, 저장, 다운로드 복원
2. 오프라인 전환, Draft 저장, 온라인 병합
3. 주석/편집/검색 UX
4. 권한 변경, 실시간 이벤트, 설정 반영

## 초기화 기준

기존 이슈별 테스트 계획과 테스트 결과는 신규 프로젝트 결과로 승계하지 않는다. 테스트 전략과 위험 기반 검증 순서만 참고한다.

## 검토 필요사항

- 하네스 프로젝트의 기본 테스트 도구를 먼저 확인해야 한다.
- MVP1은 ID/PW, 이메일, 카카오/네이버/구글 로그인 선택 흐름과 설정별 이메일 인증 동작을 검증해야 한다.
- Playwright E2E는 MVP1에서는 로그인 핵심 여정에 최소 도입하고, PDF 렌더링과 캔버스 검증은 2차 이후에 확장한다.
- 업로드/다운로드 복원 테스트는 샘플 PDF와 예상 산출물 기준이 필요하다.
