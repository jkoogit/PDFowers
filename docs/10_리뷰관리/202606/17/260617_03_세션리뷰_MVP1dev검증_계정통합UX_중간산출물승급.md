## 4. QNAP Container Station 배포 방식 검토

현재 dev compose는 `ghcr.io/jkoogit/pdfowers:dev` 고정 태그와 `pull_policy: always`를 사용한다. 같은 태그에 새 이미지가 발행되어도 실행 중 컨테이너는 자동으로 새 이미지로 바뀌지 않는다. 따라서 새 이미지를 반영하려면 pull 후 컨테이너 교체가 필요하다.

다만 매번 강제 재생성을 기본 절차로 둘 필요는 없다. 권장 기준은 `이미지 pull -> compose up -d -> smoke 검증`이다. CLI 기준으로는 `--force-recreate` 없이 `docker compose pull pdfowers_dev`와 `docker compose up -d pdfowers_dev`를 우선 사용한다. QNAP UI의 `Recreate`는 새 이미지나 환경변수 변경을 반영해야 할 때는 정상적인 교체 절차지만, 이미지 ID와 환경변수가 모두 같을 때 반복 실행하는 것은 과하다.
