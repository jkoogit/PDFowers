## 2. 작업 배경

MVP1 인증 검수 서버는 계정 통합 요청과 승인 도메인 흐름을 제공하지만, 검수자가 확인할 UX 기준과 사용자 알림 기준이 부족했다. 이번 세션에서는 계정 통합 요청/승인 시 어떤 정보를 사용자에게 보여줄지, 어떤 알림 이벤트를 남길지, 실제 이메일 발송 실패를 어떻게 검수할지 정리하고 구현했다.

## 5. 구현 요약

- 계정 통합 요청 생성 시 대상 계정에 `ACCOUNT_MERGE_REQUESTED` 샘플 이벤트와 이메일 이벤트를 생성한다.
- 계정 통합 승인 완료 시 요청 계정과 대상 계정 양쪽에 `ACCOUNT_MERGE_APPROVED` 샘플 이벤트와 이메일 이벤트를 생성한다.
- SMTP 설정이 없거나 발송이 실패해도 핵심 계정 통합 상태 변경은 유지하고, 이메일 이벤트를 `failed` 상태로 남긴다.
- 검수화면은 알림 개수, 최근 알림 이벤트, provider user id 마스킹 값을 표시한다.
- 실제 SMTP 발송은 `SMTP_HOST`, `SMTP_PORT`, `SMTP_SECURE`, `SMTP_USER`, `SMTP_PASS`, `SMTP_FROM` 환경변수로 제어한다.

## 8. 보안/운영 메모

- 실제 SMTP 계정, DB 비밀번호, OAuth Client Secret은 문서와 PR 본문에 원문으로 남기지 않는다.
- 알림 이벤트 본문에는 provider user id 원문과 토큰을 포함하지 않는다.
- OAuth access token과 refresh token은 MVP1에서 저장하지 않는다.
- SMTP 발송 실패는 계정 통합 실패로 처리하지 않고 검수 이벤트에서 추적한다.
