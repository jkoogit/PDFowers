## 2. 작업 배경

MVP1 검수 서버를 로컬 실행에서 dev, stg, prd 운영 흐름으로 확장해야 한다. dev 환경은 NAS Container Station에서 앱 컨테이너로 운영하고, DB는 별도 우분투 PostgreSQL 서비스를 사용한다. stg/prd는 Cloudtype 배포를 기준으로 한다.

초기에는 NAS Container Station에서 GitHub `dev` 브랜치를 직접 build context로 사용하는 방식을 검토했다. 실제 Container Station 로그에서 Docker Build 환경에 `git`이 없어 GitHub URL build context가 실패하는 것을 확인했다.

```text
exec: "git": executable file not found in $PATH
```

이에 따라 NAS는 이미지를 빌드하지 않고 GHCR 이미지를 pull하는 방식으로 변경했다.

## 4. 주요 발견사항

| 구분 | 발견사항 | 조치 |
| :--- | :--- | :--- |
| QNAP build context | GitHub URL build context는 내부 `git` 부재로 실패 | GHCR image pull 방식으로 전환 |
| NAS DB 구성 | DB는 NAS compose 대상이 아니라 우분투 PostgreSQL 설치 서비스 사용 | compose에서 DB/pgAdmin 서비스 제외 |
| 앱 볼륨 | MVP1 인증 검수 범위에서는 앱 로컬 영속 저장소가 필요 없음 | 앱 컨테이너 무상태 유지 |
| GHCR 접근 | 이미지가 private이면 NAS pull이 `denied`로 실패 | GHCR public 공개 또는 NAS registry 인증 필요 |
| 카카오 callback | NAS 도메인 운영에서는 `localhost` callback 사용 불가 | `https://fowersdev.pdfrend.com/auth/kakao/callback` 기준 문서화 |

## 7. 보안 메모

- DB 비밀번호, 카카오 Client Secret, GHCR 토큰은 문서와 PR 본문에 원문으로 남기지 않는다.
- 이번 커밋 전 staged diff에서 세션 중 노출된 DB/Kakao secret 패턴이 포함되지 않았음을 확인했다.
- 세션 중 채팅에 노출된 DB 비밀번호와 카카오 Secret은 실제 운영 키라면 교체를 권장한다.

## 8. 결론

배포 구조는 `task/* -> dev` PR 병합 후 GitHub Actions가 GHCR dev 이미지를 만들고, NAS는 해당 이미지를 수동 pull/recreate하는 흐름으로 확정했다. 이 방식은 QNAP Container Station의 GitHub build context 제약을 회피하고, 이후 stg/prd Cloudtype 운영과도 같은 Dockerfile 기준을 공유한다.
