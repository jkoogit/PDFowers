## 작업 요약

1. 세션 워크플로에서 `#세션시작` 트리거를 제거하고 `#세션마무리`, `#브랜치승급`, `#세션종료` 기준을 문서화했다.
2. `main`을 GitHub 기본 운영 브랜치이자 서비스 관점의 prd로 정리하고, `dev -> stg -> main` 승급 기준을 갱신했다.
3. Kakao 실제 로그인 검증은 운영자 브라우저 수동 검증으로 정리하고, Codex 자동 smoke는 설정과 authorize redirect까지만 확인하도록 범위를 분리했다.
4. 운영 호스팅은 NAS와 Cloudtype 중 추후 결정하되, 결정 전까지 운영 도메인을 NAS prd 후보에 연결하는 기준을 문서화했다.
5. 이메일 인증 정책을 서비스 사용 차단 수단이 아니라 알림 수신 신뢰 수단으로 재정의했다.
6. 이메일 인증 필수 정책에서도 로그인은 허용하고, 사용자정보 수정 화면에서 인증 안내와 인증 기능을 제공하는 흐름으로 정리했다.
7. 네이버/구글 실제 OAuth 연동을 MVP1 구현 대상으로 포함했다.
8. 계정 통합 요청자/대상자 목록, 상태, 승인/거절/삭제 버튼, 삭제 정책, 완료/잠금 메시지를 구체화했다.

## 결정 사항

| 항목 | 결정 |
| :--- | :--- |
| Kakao 실제 로그인 | 운영자가 브라우저에서 수동 검증한다. Codex 자동 확인은 authorize redirect까지로 제한한다. |
| 운영 호스팅 | NAS와 Cloudtype 중 추후 결정한다. 결정 전까지 운영 도메인은 NAS prd 후보에 연결한다. |
| 인증서/CA | 정상 공인 도메인과 정상 인증서 체인을 기본 기준으로 둔다. `NODE_EXTRA_CA_CERTS`는 dev smoke 진단 보조로만 사용한다. |
| 이메일 인증 | 알림 수신 신뢰 수단으로 둔다. 필수 정책이어도 로그인과 서비스 사용은 차단하지 않는다. |
| 이메일 인증 화면 | 별도 완료 화면 없이 회원가입 화면과 사용자정보 수정 화면에서 진행/완료 상태를 표시한다. |
| 이메일 인증 재발송 | 만료 1시간, 재발송 시 기존 인증 폐기, 60초 쿨다운, 1시간 최대 5회, 실패 확인 5회 제한을 기본 후보로 둔다. |
| 네이버/구글 OAuth | MVP1 구현 대상으로 포함한다. Kakao와 같은 start/callback/profile normalize와 state 검증을 적용한다. |
| 계정 통합 UX | 사용자정보 화면의 통합계정 목록에서 요청자/대상자별 상태와 버튼을 제공한다. |

## 후속 작업

1. 다음 세션에서 이메일 인증 실제 API와 화면 흐름을 구현한다.
2. `system_property` 또는 동등한 시스템 설정 저장 구조를 설계하고 migration/test를 추가한다.
3. `email_verification_request` 또는 동등한 인증 요청 저장 구조를 설계한다.
4. 기존 `EMAIL_VERIFICATION_REQUIRED` 로그인 차단 테스트를 로그인 허용 후 사용자정보 화면 안내 테스트로 교체한다.
5. Naver/Google 실제 OAuth client, provider profile normalize, 실패/timeout/민감정보 비노출 테스트를 추가한다.
6. 계정 통합 사용자정보 화면 목록, 대상자 승인/거절/삭제, 요청자 삭제 정책을 구현한다.
