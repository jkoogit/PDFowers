# 260607_01 문서리뷰 - 인증/계정 정책 정리

## 리뷰 대상

- 본인인증 제외 여부
- 카카오/네이버/구글 간편로그인 채택 여부
- 이메일 동일성 기반 계정 통합 위험
- 벤더 ID 기반 로그인 수단 연결 및 계정 통합 정책
- 계정, 개인정보, DB 계정, 인증키 등 민감정보 관리 방향

## 정리된 결정

1. 휴대폰 본인확인과 실명확인은 비용 문제로 MVP 범위에서 제외한다.
2. 카카오, 네이버, 구글 간편로그인은 구현 후보로 유지한다.
3. 간편로그인은 본인인증이 아니며 법적 동일인 확인으로 사용하지 않는다.
4. 서비스 내부 회원은 `user_id`로 관리하고, 외부 계정은 로그인 수단으로 연결한다.
5. 이메일, 이름, 전화번호 동일성만으로 계정을 자동 통합하지 않는다.
6. 제공자별 고유 ID `(provider, provider_user_id)`를 기준으로 로그인 수단을 식별한다.
7. 로그인 상태에서 추가 간편로그인을 등록할 수 있다.
8. 연결하려는 벤더 ID가 이미 다른 내부 계정에 연결되어 있으면 자동 통합하지 않고 사용자 동의 기반 계정 통합 절차로 전환한다.
9. 계정 통합 시 대표 계정을 기준으로 문서, 주석, 공유 권한, 설정, 인증수단을 이전하고 보조 계정은 `merged` 상태로 보관한다.
10. 실제 시크릿, DB 비밀번호, 계좌, 개인정보 원문은 문서/이슈/리뷰/채팅/Git에 기록하지 않는다.

## 검토 시나리오

```text
1. A01 ID 계정 등록
2. A02 카카오 계정 등록(kakao01)
3. A01 ID 계정 로그인
4. A01에서 카카오 간편로그인 등록(kakao01) 시도
5. 시스템이 kakao01이 A02에 연결되어 있음을 확인
6. 시스템이 계정 통합 안내 표시
7. 사용자 동의 후 A01/A02 통합
```

## 발견한 논리 위험

- `provider_user_id`가 같다는 것은 같은 벤더 계정 인증에 성공했다는 의미지만, 법적 동일인 보장은 아니다.
- 자동 통합은 사용자가 예상하지 못한 데이터 이전을 만들 수 있다.
- 이메일 동일성은 통합 근거로 위험하다.
- 통합 대상 계정에 문서, 공유 권한, 설정이 있을 수 있으므로 통합 전 안내와 감사 로그가 필요하다.
