## 2. 작업 배경

MVP1 인증 구현은 순수 도메인 테스트 중심으로 정리되어 있었고, 실제 PostgreSQL/Drizzle 기반 통합 테스트와 DB 관리이력은 아직 분리되지 않았다. 사용자는 MVP1 작업 전 정리할 내용을 확인한 뒤, 설정한 DB를 기준으로 단위 테스트와 통합 테스트를 용도에 맞게 작성하고, 시스템 DB 관리이력을 다음 시스템 초기데이터 구축 기준으로 남기도록 요청했다.

## 5. 테스트와 DB 기준

| 범위 | 기준 |
| :--- | :--- |
| 단위 테스트 | DB 없이 인증 도메인 순수 함수 검증 |
| 통합 테스트 | `TEST_DATABASE_URL` 또는 `DATABASE_URL`이 있으면 PostgreSQL에 저장 후 트랜잭션 rollback |
| DB 스키마 | PostgreSQL + Drizzle ORM 기준 |
| 시스템 데이터 | 공통코드, 시스템 설정, 기본 정책값은 관리 대상 |
| 활동 데이터 | 회원정보, 문서정보, 실제 감사 로그 row, Job 실행 row는 관리 제외 |

## 7. 남은 위험과 주의사항

- 현재 셸에는 `DATABASE_URL`, `TEST_DATABASE_URL`이 없어 실제 PostgreSQL 통합 테스트 본문은 실행하지 못했다.
- `ensureAuthSchema`는 테스트 편의를 위한 최소 DDL 보조 함수이며, 운영 적용 기준은 Drizzle migration이다.
- 공통코드 전용 테이블과 seed 파일은 아직 구현하지 않았다. 이번 세션에서는 관리이력 문서에 초기 코드 후보를 남겼다.
- API, 세션, OAuth 실제 제공자 연동, 이메일 인증 발송/검증은 아직 구현되지 않았다.
- `npm install` 과정에서 `drizzle-kit` 계열 개발 의존성에 moderate 취약점 4건 경고가 표시되었다. 별도 보안 점검이 필요하다.
