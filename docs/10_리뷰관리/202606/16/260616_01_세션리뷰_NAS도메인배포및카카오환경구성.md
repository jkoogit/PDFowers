# 세션 리뷰 - NAS 도메인 배포와 카카오 환경구성

## 개요

- 일자: 2026-06-16
- 작업 브랜치: `task/nas-배포yml_codex`
- 관련 이슈: #51
- 목표: QNAP NAS 개발서비스 외부 접속 구성을 정리하고, 카카오 OAuth Redirect URI를 배포환경별 도메인 변경에 대응하도록 개선한다.

## 진행 내용

1. QNAP NAS 개발서비스 배포 흐름을 점검했다.
   - Docker Station의 MVP1 검수 서비스는 `http://192.168.219.112:4173`에서 정상 동작했다.
   - QNAP 기본 리버스 프록시와 인증서 발급 과정에서 `fowersdev.pdfrend.com`은 ACME HTTP-01 검증이 안정적으로 통과하지 못했다.
   - 개발 검증용으로는 QNAP DDNS `jkok2.myqnapcloud.com`과 QNAP에서 발급한 Let's Encrypt 인증서를 임시 사용하기로 했다.
   - 외부 모바일망에서 `https://jkok2.myqnapcloud.com` 접속 시 PDFowers MVP1 검수 화면이 표시되는 것을 확인했다.

2. NAS 배포 예시를 정리했다.
   - QNAP Container Station용 compose 예시를 추가했다.
   - NAS `.env.example`과 compose 파일에 `APP_BASE_URL`, `KAKAO_REDIRECT_PATH`, `NPM_CONFIG_OPTIONAL`을 반영했다.
   - 기존 `KAKAO_REDIRECT_URI` 직접 지정 방식은 호환용 override로 유지했다.

3. 카카오 Redirect URI 구성을 개선했다.
   - `APP_BASE_URL`과 `KAKAO_REDIRECT_PATH`를 조합해 Redirect URI를 생성하도록 분리했다.
   - `KAKAO_REDIRECT_URI`가 있으면 기존처럼 최우선으로 사용한다.
   - 도메인에 프로토콜이 없으면 `https://`를 기본으로 보정한다.

4. 운영 판단을 문서화했다.
   - QNAP 내장 리버스 프록시와 Nginx Proxy Manager의 역할 차이를 정리했다.
   - 개발서비스는 QNAP DDNS로 우선 검증하고, 운영서비스는 Cloudtype 유지, NAS Nginx Proxy Manager, 별도 인프라 중 결정하기로 보류했다.

## 후속 작업

1. NAS Docker Station 환경변수에 아래 값을 적용하고 컨테이너를 재기동한다.
   - `APP_BASE_URL=https://jkok2.myqnapcloud.com`
   - `KAKAO_REDIRECT_PATH=/auth/kakao/callback`
   - `KAKAO_REDIRECT_URI`는 직접 override가 필요할 때만 사용한다.
2. `https://jkok2.myqnapcloud.com/auth/kakao/config-status`에서 카카오 설정 상태를 확인한다.
3. 카카오 개발자 콘솔 Redirect URI에 `https://jkok2.myqnapcloud.com/auth/kakao/callback`이 등록된 상태로 실제 로그인 플로우를 검증한다.
4. 운영 전환 전 `fowersdev.pdfrend.com` 사용 여부와 Nginx Proxy Manager 도입 여부를 결정한다.
