# 01. 정책관리

## 목적

서비스 운영과 기능 구현의 기준이 되는 정책을 관리한다. 정책은 기획, 설계, 테스트, 운영 문서에서 참조하는 상위 기준이다.

## 기존 참고 문서에서 유지할 핵심

- 신규 가입 사용자 기본 업로드 용량은 정책으로 관리한다.
- 사용자의 실제 사용량이 할당량을 초과하면 추가 업로드를 제한한다.
- 공유받은 문서는 수신자의 업로드 용량에 포함하지 않는다.
- 문서 버전은 브랜치/머지 개념을 참고하되, 실제 구현 모델은 신규 설계에서 확정한다.
- 주석 수정은 실시간 저장과 명시적 체크포인트를 구분한다.
- 오프라인 충돌은 자동 처리만으로 확정하지 않고, 충돌 UI를 제공하는 방향을 검토한다.
- 주석과 목차 데이터는 구조화된 형태로 저장해야 하며, JSONB 사용 여부는 기술 스택 확정 후 결정한다.
- 회원의 최종 식별자는 인증수단이 아니라 내부 회원계정이다.
- 환경 변수와 민감정보는 코드와 문서에 직접 노출하지 않는다.

## 초기화 기준

기존 작성 이력은 승계하지 않는다. 기존 정책 중 기술 전제가 섞인 항목은 하네스 기반 아키텍처와 배포 환경이 확정된 뒤 본문에 다시 반영한다.

## 검토 필요사항

- 본인인증은 MVP에서 제외하고 카카오/네이버/구글 간편로그인을 채택한다.
- 회원 기본키는 UUID를 기본 후보로 두고 상세 데이터 설계에서 확정한다.
- NAS, S3, 하네스 제공 스토리지 중 운영 기준 저장소를 결정해야 한다.
- `10_리뷰관리` 경로를 프로젝트 지침에 정확히 반영해야 한다.
