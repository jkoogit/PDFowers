# PDFowers 신규 프로젝트 문서 관리 가이드

## 문서 전환 목적

이 `docs` 폴더는 기존 `참고_docs`의 기획, 설계, 분석, 정책 자료를 검토하여 하네스 기반 신규 프로젝트에서 다시 사용할 업무 문서 체계로 재정리한 공간이다.

기존 문서의 작성 이력, 완료 이력, 리뷰 이력, 이슈 진행 기록은 신규 프로젝트의 사실로 승계하지 않는다. 기존 내용은 참고 근거로만 사용하며, 신규 프로젝트에서 확정된 내용만 각 관리 문서에 다시 기록한다.

## 운영 원칙

- 신규 문서의 기준 경로는 `docs/`다.
- 모든 관리 그룹은 `README.md`를 진입 문서로 둔다.
- 과거 `참고_docs`의 작성 이력은 초기화한다.
- `08_이슈관리`, `10_리뷰관리`는 과거 기록을 이관하지 않고, 신규 프로젝트 진행 중 새로 작성한다.
- AI/Manus/WebDev 전제는 하네스 기반 프로젝트 전제로 재검토한 뒤 확정한다.
- 논리적 모순이나 확정 전제는 [논리모순 검토 대장](./08_이슈관리/논리모순_검토대장.md#검토-항목)에 먼저 등록하고, 검토 후 관련 문서를 현행화한다.

## 신규 문서 작성 규칙

문서 파일명은 `번호_문서명.md`를 기본으로 한다. 이슈나 리뷰처럼 진행 중 새로 쌓이는 문서는 날짜 기반 파일명을 사용할 수 있다.

권장 문서 구조:

```markdown
# 문서명

## 목적

## 적용 범위

## 주요 내용

## 검토 필요사항

## 관련 문서

## 작업 이력

| 작업일시 | 작업 에이전트 | 작성자 | 내용 한 줄 요약 |
| :--- | :--- | :--- | :--- |
```

문서 작성 및 현행화 시 다음 규칙을 적용한다.

- 모든 신규/현행 문서는 `docs/` 아래에 작성한다.
- 다른 문서를 언급할 때는 가능한 한 상대 링크와 섹션 앵커를 함께 추가한다.
- 표, 목록, 검토 항목처럼 추적과 관리가 필요한 항목에는 ID를 부여한다.
- 산출물 문서의 항목 ID는 [산출물 항목 ID 규칙](./00_산출물/README.md#산출물-항목-id-규칙)을 따른다.
- Notion 비교검토처럼 반영 여부를 점검하는 문서는 항목 ID 앞에 상태 표시를 붙인다.
- 비교검토 상태값은 `보완후보`, `충돌,재검토`, `후순위`, `동일` 네 가지로 관리한다.
- 비교검토 항목 ID 앞 표시는 `[=] 동일`, `[^] 보완후보`, `[@] 충돌,재검토`, `[~] 후순위`를 사용한다.
- 상태 컬럼에는 표시 기호를 넣지 않고 상태값만 기록한다.
- 참고 문서 원문은 신규 프로젝트의 확정 내용으로 바로 승계하지 않고, 비교검토 후 현행 문서에 필요한 내용만 보완한다.

## 작업 이력 작성 규칙

모든 Markdown 문서는 하단에 `## 작업 이력` 섹션을 둔다.

작업 이력 표는 다음 형식을 사용한다.

```markdown
## 작업 이력

| 작업일시 | 작업 에이전트 | 작성자 | 내용 한 줄 요약 |
| :--- | :--- | :--- | :--- |
| 2026-06-08 02:20 KST | Codex | jkoogi | 문서 작업 이력 섹션 추가 |
```

작업 이력 작성 원칙:

- 작업일시는 `YYYY-MM-DD HH:mm KST` 형식으로 기록한다.
- 작업 에이전트는 실제 작업 주체를 기록한다. 예: `Codex`
- 작성자는 요청 또는 검토 책임자를 기록한다. 예: `jkoogi`
- 내용 한 줄 요약은 문서 변경 목적을 한 줄로 쓴다.
- 문서를 의미 있게 수정한 경우 기존 이력 아래에 새 행을 추가한다.
- 과거 `참고_docs`의 작성 이력은 신규 `docs`의 작업 이력으로 승계하지 않는다.

## 참고 문서 처리 기준

`참고_docs`는 원본 참고 자료로 보존한다. 신규 `docs`에는 다음 기준으로만 내용을 반영한다.

- 정책, 요구사항, 도메인 경계처럼 제품 정체성과 직접 관련된 내용은 우선 승계 후보로 둔다.
- Manus OAuth, Cloudtype, NAS/S3, Node.js/tRPC/Drizzle처럼 실행 환경 또는 구현 기술에 묶인 내용은 하네스 기반에서 재검토한다.
- 완료된 이슈, 리뷰, 테스트 결과, 과거 커밋 근거는 신규 프로젝트의 현재 상태로 간주하지 않는다.
- 깨진 링크, 깨진 인코딩, 과거 폴더 번호 체계는 새 문서 체계에서 정리한다.
