# ADR-005. 인증 구현 방식 선택

## 상태

승인됨

## 배경

[ADR-003](./ADR-003_인증방식선택.md)은 카카오, 네이버, 구글 간편로그인과 승인 기반 계정 통합 정책을 확정했다. MVP1 구현을 시작하려면 세션, OAuth 클라이언트, 토큰 저장 여부, 모의 제공자 테스트 전략을 추가로 확정해야 한다.

## 결정

MVP1 인증 구현은 서버 세션 + 직접 OAuth 클라이언트를 채택한다.

1. 로그인 상태는 서버 세션으로 관리한다.
2. OAuth `state`와 계정 통합 승인 상태는 서버 저장소에서 관리한다.
3. Passport.js는 Express 채택 시 보조 후보로 두되 기본 구현으로 채택하지 않는다.
4. JWT는 MVP1 기본 사용자 세션 방식으로 채택하지 않는다.
5. OAuth access token과 refresh token은 MVP1에서 저장하지 않는다.
6. 코딩 착수 단계에서는 실제 제공자 호출 대신 모의 OAuth 제공자 어댑터로 도메인 흐름을 먼저 검증한다.

## 결과

### 긍정적 영향

- 계정 통합 직후 세션 상태와 권한 반영이 단순하다.
- OAuth 제공자별 차이를 포트와 어댑터로 격리할 수 있다.
- 외부 토큰 저장을 피하므로 초기 민감정보 관리 범위가 줄어든다.

### 부정적 영향

- 제공자별 OAuth 구현과 보안 검증 책임을 직접 부담한다.
- 모바일 앱이나 외부 API 토큰 발급이 필요해지면 별도 토큰 전략이 필요하다.

## 후속 작업

- `OAuthProviderPort`와 모의 제공자 어댑터를 먼저 구현한다.
- 실제 카카오, 네이버, 구글 연동 전 공식 문서 기준으로 scope, callback, 이메일 제공 정책을 검증한다.
