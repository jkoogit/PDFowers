# ADR-004. API 방식 선택

## 상태

승인됨

## 배경

MVP1 인증 기능은 회원가입, 로그인, OAuth 콜백, 로그인 수단 연결, 계정 통합 승인처럼 명령형 흐름이 많다. PDFowers는 장기적으로 문서 처리와 외부 도구 연동 가능성이 있으므로 클라이언트 내부 타입 공유만으로 API 계약을 관리하면 부족하다.

## 결정

MVP1 API 방식은 REST + OpenAPI를 채택한다.

1. 인증 API는 HTTP 메서드와 경로가 명확한 REST 엔드포인트로 제공한다.
2. 입력 검증 스키마와 OpenAPI 문서가 어긋나지 않도록 같은 계약을 기준으로 관리한다.
3. tRPC는 내부 TypeScript 클라이언트 전용 생산성 도구로만 후순위 검토한다.
4. 서버 액션이나 프레임워크 내장 RPC는 핵심 인증 API의 기본 방식으로 채택하지 않는다.

## 결과

### 긍정적 영향

- 외부 도구, 테스트 스크립트, 운영 검증에서 API를 호출하기 쉽다.
- 인증 오류 코드와 계정 통합 상태를 명시적 응답 계약으로 관리할 수 있다.
- 프론트엔드 프레임워크 변경 시 API 경계가 유지된다.

### 부정적 영향

- TypeScript 클라이언트 타입 공유를 자동으로 얻으려면 생성 도구가 필요하다.
- OpenAPI 문서와 실제 검증 스키마의 동기화 절차가 필요하다.

## 후속 작업

- 인증 API 경로와 오류 코드를 구현 계획에 반영한다.
- OpenAPI 생성 또는 검증 도구는 패키지 설치 가능 시점에 결정한다.
