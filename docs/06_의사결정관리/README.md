# 06. 의사결정관리

## 목적

주요 기술, 아키텍처, 운영 방식의 결정과 변경 사유를 ADR 형태로 관리한다.

## 기존 참고 문서에서 확인한 결정 후보

| 기존 결정 | 신규 프로젝트 처리 |
| :--- | :--- |
| Kotlin/Spring Boot 대신 Node.js + Express + tRPC 선택 | 하네스 구조 확인 후 재승인 필요 |
| PostgreSQL + Drizzle ORM 사용 | 데이터 모델과 하네스 호환성 확인 후 재승인 필요 |
| 카카오/네이버/구글 OAuth + 이메일 인증 | 인증 범위와 비용, 개발 공수 검토 후 재승인 필요 |
| DDD 기반 도메인 분리 | 기본 설계 방향으로 유지 가능 |
| dev/stg/main 브랜치 승격 | 신규 저장소/배포 전략에 맞게 재검토 |

## ADR 상태값

- `제안됨`: 선택지가 정리되었으나 결정 전
- `승인됨`: 신규 프로젝트 기준으로 채택
- `대체됨`: 새 결정으로 교체
- `보류`: 지금 결정하지 않음

## 초기화 기준

기존 ADR 번호와 승인 상태는 참고만 한다. 신규 프로젝트에서 다시 승인되지 않은 결정은 `승인됨`으로 표기하지 않는다.

## 검토 필요사항

- 하네스 전환 결정은 최상위 ADR로 먼저 작성해야 한다.
- 인증 방식은 [ADR-003 인증 방식 선택](./ADR-003_인증방식선택.md#결정)에 우선 반영했으며, 하네스 인증 구조 검토 결과에 따라 보완한다.
- 기존 일정과 이슈 번호를 근거로 한 결정은 신규 프로젝트에서 무효화한다.
