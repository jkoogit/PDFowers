# ADR-007. 비동기 처리 선택

## 상태

승인됨

## 배경

MVP1 계정 통합은 AuthIdentity 이전, 보조 계정 상태 변경, 감사 로그 기록처럼 일관성이 중요한 변경을 포함한다. 동시에 통합 완료 알림, 후속 재색인, 대량 문서 소유권 이전 같은 작업은 응답 지연과 재시도 요구가 생길 수 있다.

## 결정

MVP1은 핵심 데이터 변경은 동기 트랜잭션으로 처리하고, 후속 작업은 DB Job Table로 분리한다.

1. 계정 통합 승인 처리의 핵심 변경은 하나의 DB 트랜잭션으로 처리한다.
2. 알림, 재색인, 대량 이전 같은 후속 작업은 `job` 테이블에 기록한다.
3. MVP1에서는 RabbitMQ 같은 외부 MQ를 도입하지 않는다.
4. 인메모리 큐는 개발/테스트 보조 용도로만 허용하고 운영 필수 작업에는 사용하지 않는다.

## 결과

### 긍정적 영향

- MVP1 인프라 복잡도를 낮춘다.
- 후속 작업의 상태와 재시도 이력을 DB에서 추적할 수 있다.
- PDF 처리 MVP에서 외부 MQ를 도입할 때 전환 지점이 명확하다.

### 부정적 영향

- DB Job Table은 고성능 메시징 기능을 제공하지 않는다.
- 워커 실행 방식과 재시도 정책을 별도로 구현해야 한다.

## 후속 작업

- `job` 모델과 상태 코드를 구현 계획에 포함한다.
- PDF 처리 MVP 시작 시 RabbitMQ 또는 호환 MQ 도입 여부를 재검토한다.
