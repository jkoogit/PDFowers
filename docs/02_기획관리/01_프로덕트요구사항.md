# 01. 프로덕트 요구사항

## 목적

PDFowers 신규 프로젝트의 제품 목표와 MVP 요구사항을 정리한다. 본 문서는 기존 참고 문서의 기능 방향을 하네스 기반 신규 프로젝트 기준으로 다시 정의한다.

## 제품 목표

PDFowers는 스캔 도서 PDF를 OCR, 목차, 주석, 버전 정보와 함께 관리하고 여러 기기에서 작업 연속성을 제공하는 PDF 작업 플랫폼이다.

## 사용자 가치

- 스캔 PDF를 검색 가능한 디지털 자산으로 관리한다.
- 태블릿, PC, 모바일 사이의 파일 이동과 버전 혼선을 줄인다.
- 주석, 목차, 북마크, 공유 권한, 버전 관리를 통해 장기 작업을 안정적으로 이어간다.
- 업로드한 PDF를 이미지, OCR, 주석/목차 데이터로 분리하고, 다운로드 시 표준 PDF로 병합한다.

## MVP 인증 범위

### 포함

- ID 기반 회원계정 생성
- 이메일 기반 로그인
- 인증 이메일 등록 및 작업 알림 발송 대상화
- 카카오 간편로그인
- 네이버 간편로그인
- 구글 간편로그인
- 이메일 회원가입 및 간편로그인 회원가입 시 ID/PW 필수 입력
- 로그인한 상태에서 간편로그인 수단 추가 연결
- 동일 벤더 ID가 이미 다른 내부 계정에 연결된 경우 계정 통합 안내

### 제외

- 휴대폰 본인확인
- 실명확인
- 주민등록 기반 동일인 인증
- 2차 인증
- 이메일 동일성만으로 자동 계정 통합
- 전화번호 동일성만으로 자동 계정 통합

## 계정 통합 사용자 시나리오

### 시나리오 A: 신규 간편로그인 연결

1. 사용자가 `A01` ID 계정으로 로그인한다.
2. 사용자가 카카오 간편로그인 등록을 선택한다.
3. 카카오 OAuth 인증을 완료한다.
4. 시스템이 `kakao01`이 기존 연결 이력이 없음을 확인한다.
5. 시스템은 `A01`에 `kakao01`을 로그인 수단으로 연결한다.

### 시나리오 B: 기존 간편로그인 계정과 통합

1. 사용자가 `A01` ID 계정을 등록한다.
2. 사용자가 별도로 카카오 계정 `kakao01`로 로그인하여 `A02` 내부 계정이 생성된 상태다.
3. 사용자가 `A01`로 로그인한 상태에서 카카오 간편로그인 등록을 선택한다.
4. 시스템이 `kakao01`이 이미 `A02`에 연결되어 있음을 확인한다.
5. 시스템은 자동 통합하지 않고 계정 통합 안내를 표시한다.
6. 사용자가 통합에 동의하면 `A01`과 `A02`를 대표 계정 기준으로 통합한다.

## 계정 통합 UX 원칙

- 사용자에게 "이미 다른 계정에 연결된 간편로그인입니다"를 명확히 안내한다.
- 두 계정의 주요 데이터 범위를 보여준다.
- 대표 계정을 선택하게 하거나, 정책상 대표 계정을 자동 선택하더라도 사전에 안내한다.
- 통합 후 되돌리기 어려운 항목을 고지한다.
- 통합 결과와 로그인 가능 수단을 확인시킨다.

## 작업 알림 요구사항

- 인증 이메일은 계정 자동 통합의 단독 근거가 아니며, 회원가입/로그인 인증, 계정 식별 보조, 작업 알림 발송 대상으로 사용한다.
- 문서 공유, 권한 변경, 문서 처리 완료/실패, 협업 작업 변경 알림은 인증 완료 및 수신 동의된 이메일로 우선 발송할 수 있어야 한다.
- 카카오 알림톡 등 추가 알림 채널은 후속 후보로 두고 비용과 운영 정책을 검토한다.
- 사용자는 알림 수신 범위를 설정할 수 있어야 하며, 세부 수신 설정은 후속 UI/UX 문서에서 정의한다.

## PDF 작업 요구사항 보완

- 다운로드 결과 파일명은 `[도서명]_[버전]_[수정일자]_[수정시간].pdf` 형식을 기본 후보로 한다.
- 다운로드한 PDF를 다시 업로드할 때 기존 문서와 버전을 추천하거나 사용자가 직접 선택할 수 있어야 한다.
- Xodo 호환 주석 타입과 PDFowers 내부 주석 데이터의 변환 기준을 검증해야 한다.
- 주석 대상 영역의 이미지 캡처, 붙여넣기, 텍스트 수정, 검색은 OCR 기능이 아니라 주석 편집 기능으로 분류한다.

## 공유 요구사항 보완

- 공유 링크는 대상 문서/버전, 공유 기간, 권한, 이력을 관리해야 한다.
- 공개 읽기 링크는 구현 대상으로 둔다.
- 공개 링크를 기본 서비스 화면 권한으로 제공할지, 별도 공개 읽기 화면으로 제공할지 결정해야 한다.
- 공개 링크 API를 기존 문서 조회 API와 공통화할지, 공개 읽기 전용 API로 분리할지 결정해야 한다.
- 공개 링크의 접근 범위, 만료, 접근 로그, 비로그인 사용자 제한은 보안 정책 결정 후 반영한다.

## AI 검색 요구사항

- AI 검색은 포털 검색처럼 키워드를 외부 서비스로 전달하는 연동 기능으로 정의한다.
- 사용자가 선택한 텍스트 또는 직접 입력한 키워드를 검색 질의로 사용한다.
- 문서 전체, 개인정보, 인증정보를 자동 전송하지 않는다.
- MVP 필수 기능 여부는 별도 우선순위 검토 후 확정한다.
