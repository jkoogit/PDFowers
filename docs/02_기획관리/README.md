# 02. 기획관리

## 목적

PDFowers의 제품 목표, 사용자 문제, 기능 요구사항, 업무 프로세스, 화면 흐름을 관리한다.

## 기존 참고 문서에서 유지할 핵심

PDFowers는 스캔 도서 PDF를 OCR, 목차, 주석, 버전 정보와 함께 관리하고 여러 기기에서 작업 연속성을 제공하는 PDF 작업 플랫폼이다.

핵심 사용자 가치는 다음과 같다.

- 태블릿, PC, 모바일 사이의 파일 이동과 버전 혼선을 줄인다.
- 스캔 이미지 PDF를 검색 가능한 디지털 자산으로 관리한다.
- 주석, 목차, 북마크, 공유 권한, 버전 관리를 통해 협업 가능한 PDF 작업 환경을 제공한다.
- 업로드한 PDF를 이미지, OCR, 주석/목차 데이터로 분리하여 관리하고, 다운로드 시 표준 PDF로 병합한다.
- 오프라인 작업 후 온라인 전환 시 변경점을 비교하고 선택적으로 병합한다.

## 주요 기능 후보

| 기능 | 요약 | 신규 프로젝트 반영 |
| :--- | :--- | :--- |
| 문서 업로드 | PDF 업로드, 문서 식별, 리소스 분리 | MVP 후보 |
| 문서 관리 | 내 문서/공유 문서, 카테고리, 메타데이터 | MVP 후보 |
| PDF 뷰어 | 목차, 주석, 북마크, 검색, 페이지 관리 | MVP 후보 |
| 주석 작업 | 형광펜, 펜, 텍스트, 도형, 이미지, 서명, 도장 | 범위 조정 필요 |
| 버전 관리 | 체크포인트, 변경 이력, 브랜치/머지 | 설계 확정 필요 |
| 공유/권한 | 공유 대상, 기간, 권한, 실시간 권한 반영 | MVP 이후 가능 |
| 오프라인 동기화 | IndexedDB 저장, 온라인 전환, 충돌 비교 | 위험도 높음 |
| AI 검색 | 포털 검색처럼 키워드를 외부 서비스로 전달하는 연동 기능 | MVP 우선순위 검토 |

## 초기화 기준

기존 문서의 `v2.0`, 작성일, 완료 상태는 승계하지 않는다. 기능 요구사항은 후보로 두고, MVP 범위는 신규 프로젝트 착수 시 다시 확정한다. 2026-06-08 기준 1차 MVP는 인증 중심 최소 릴리스 단위로 정리한다.

## 검토 필요사항

- 단계적 MVP 범위는 [요구사항 명세서 - MVP 범위](../00_산출물/01_프로젝트산출물/01_요구사항명세서.md#6-mvp-범위)를 기준으로 관리한다.
- AI 검색은 MVP 후순위 기능으로 두고, 단순 링크 연동을 우선 예상한다.
- 기존 화면정의서의 이미지 경로는 신규 프로젝트에서 사용할 수 없으므로 재작성 또는 자산 재배치가 필요하다.
