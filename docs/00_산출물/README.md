# 00. 산출물 관리

## 목적

이 폴더는 `docs/` 아래의 기획, 정책, 설계, 기술 검토 문서를 기준으로 대외 산출물 또는 프로젝트 기준 산출물 형태로 재정리한 문서를 관리한다.

## 폴더 구성

| 폴더 | 산출물 분류번호 | 용도 |
| :--- | :--- | :--- |
| `01_프로젝트산출물` | `01` | PDFowers 제품/시스템 전체 구현 대상 산출물 |
| `02_하네스산출물` | `02` | 하네스 기반 구현, 테스트, 품질 관리 산출물 |

## 산출물 항목 ID 규칙

문서 안의 표, 목록, 검토 항목처럼 추적과 관리가 필요한 항목은 다음 형식의 ID를 부여한다.

```text
{산출물그룹 2자리}{문서번호 2자리}{장번호 2자리}_{항목순번 3자리}
```

실제 항목 예시:

- `000103_001`: `00_산출물` / `01_요구사항명세서` / `3. 전체 구현 대상` / 1번 항목
- `000203_001`: `00_산출물` / `02_시스템설계서` / `3. 시스템 구성요소` / 1번 항목
- `000308_001`: `00_산출물` / `03_아키텍처문서` / `8. 아키텍처 결정 현황` / 1번 항목

관리 원칙:

- `01_프로젝트산출물`의 기존 작성 문서는 사용자 예시와 맞추기 위해 `00 + 문서번호 + 장번호` 형식을 유지한다.
- `02_하네스산출물`은 폴더번호를 드러내기 위해 하위 문서번호를 `02-01`, `02-02`처럼 관리하고, ID 접두어는 `000201장번호_순번` 형식을 사용한다.
- 항목이 삭제되거나 다른 장으로 이동하더라도 기존 ID는 재사용하지 않는다.
- 같은 의미의 항목을 다른 문서에서 참조할 때는 새 ID를 만들지 않고 원 ID를 함께 기록한다.
- 세부 구현 문서에서 요구사항을 검증할 때는 요구사항 ID, 설계 ID, 테스트 ID를 매핑한다.

## 비교검토 항목 표시 규칙

기획, 정책, 설계 문서 보완 여부를 점검하는 비교검토 문서는 항목 ID 앞에 상태 표시를 붙인다.

| 표시 | 상태 | 의미 |
| :--- | :--- | :--- |
| `[=]` | `동일` | 현행 문서에 같은 수준으로 반영됨 |
| `[^]` | `보완후보` | 현행 문서 보완 검토 또는 반영 대상 |
| `[@]` | `충돌,재검토` | 현행 결정과 충돌하거나 별도 의사결정 필요 |
| `[~]` | `후순위` | 후속 MVP 또는 백로그로 관리 |

표기 예시:

```markdown
| - [^] `NOTION-CMP-021` | 공개 읽기 링크 | ... | `보완후보` |
```

상태 컬럼은 `보완후보`, `충돌,재검토`, `후순위`, `동일`처럼 상태값만 기록하고, 상태 표시 기호는 항목 ID 앞에만 둔다.

- 구현 방식과 보안 기준은 [04_기술관리](../04_기술관리/README.md#하네스-전환-기준)와 [의사결정관리 ADR](../06_의사결정관리/README.md#신규-작성-대상)을 함께 확인한다.
