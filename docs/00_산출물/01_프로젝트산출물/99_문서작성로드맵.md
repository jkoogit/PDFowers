# 프로젝트 산출물 작성 로드맵

## 1. 목적

프로젝트 산출물과 하네스 산출물 사이의 중복 가능성을 정리하고, 각 문서의 작성 시점을 제안한다.

## 2. 중복 검토 및 통합 방안

| 중복 후보 | 중복 내용 | 용도 구분 | 통합 방안 |
| :--- | :--- | :--- | :--- |
| 요구사항 명세서 / 하네스 기획서 | 구현 대상과 테스트 대상 범위 | 요구사항 명세서는 제품 기능 기준, 하네스 기획서는 검증 환경과 역할 기준 | 요구사항 명세서를 원천으로 두고 하네스 기획서는 테스트 대상 추적표로 참조 |
| 시스템 설계서 / 하네스 설계서 | 구성요소, 인터페이스, 데이터 흐름 | 시스템 설계서는 제품 시스템, 하네스 설계서는 테스트 실행 시스템 | 통합하지 않고 인터페이스 표준만 상호 링크 |
| 아키텍처 문서 / 시뮬레이션 및 모의 환경 구성 문서 | 인프라와 외부 의존성 | 아키텍처는 운영 후보 구조, 시뮬레이션 문서는 대체/모의 구성 | 운영 구조는 아키텍처에 두고 모의 구성은 하네스 문서로 분리 |
| 정책 문서 / 코드 리뷰 및 품질 관리 지침서 | 코딩 표준, 보안, 품질 게이트 | 정책 문서는 프로젝트 공통 규칙, 품질 지침서는 리뷰 실행 기준 | 정책 문서를 상위 문서로 두고 리뷰 지침서는 체크리스트화 |
| 테스트 계획서 / 자동화 테스트 플랜 | 테스트 범위와 실행 전략 | 테스트 계획서는 제품 검증 전체, 자동화 테스트 플랜은 자동 실행 범위 | 수동/인수 테스트는 프로젝트 문서, 자동화 실행은 하네스 문서 |
| 테스트 케이스 / 테스트 스크립트 목록 | 검증 시나리오 | 테스트 케이스는 기대 행위, 스크립트 목록은 실제 실행 파일 | 테스트 케이스 ID와 스크립트 ID를 매핑 |
| 배포 및 운영 가이드 / 실행 및 로그 분석 가이드 | 운영 실행, 장애 분석 | 배포 가이드는 서비스 운영, 로그 분석 가이드는 하네스 실행 결과 분석 | 운영 로그 기준은 배포 가이드, 테스트 로그 판독은 하네스 가이드 |

## 3. 프로젝트 산출물 작성 시점

| 순서 | 문서 | 권장 작성 시점 | 선행 조건 |
| :---: | :--- | :--- | :--- |
| 1 | 요구사항 명세서 | 프로젝트 기준선 수립 시점 | 기획/정책/도메인 문서 1차 정리 |
| 2 | 시스템 설계서 | 요구사항 명세서 1차 승인 직후 | 핵심 도메인과 인증 정책 확정 |
| 3 | 아키텍처 문서 | 시스템 설계서 초안 작성 직후 | 배포/스토리지 검토 항목 식별 |
| 4 | 데이터베이스 설계서 | User/AuthIdentity/Audit와 문서 도메인 관계 확정 후 | 도메인 모델, 식별자 정책 |
| 5 | API 명세서 | 인증/계정 통합 흐름과 주요 도메인 유스케이스 확정 후 | 시스템 설계서, DB 초안 |
| 6 | UI/UX 디자인 문서 | API 상세 확정 전 | 요구사항 명세서, 계정 통합 UX 원칙 |
| 7 | 테스트 계획서 및 테스트 케이스 | 요구사항과 API 초안 확정 후 | 요구사항 ID, API 흐름 |
| 8 | 배포 및 운영 가이드 | Cloudtype/NAS Docker 운영 방안 결정 후 | 아키텍처 결정 ADR |
| 9 | 사용자 매뉴얼 | 주요 화면 구현 완료 후 | UI/UX 문서, 구현 화면 |
| 10 | 프로젝트 관리 문서 | 요구사항 기준선 승인 직후부터 | 마일스톤과 리스크 식별 |

## 4. 하네스 산출물 작성 시점

| 순서 | 문서 | 권장 작성 시점 | 선행 조건 |
| :---: | :--- | :--- | :--- |
| 1 | 하네스 기획서 | 요구사항 명세서 1차 작성 직후 | 테스트 대상 기능 목록 |
| 2 | 하네스 설계서 | 시스템 설계서와 아키텍처 초안 작성 직후 | 모듈 경계, 인터페이스 후보 |
| 3 | 정책 문서 | 하네스 구현 착수 전 | 보안/코딩/테스트 원칙 |
| 4 | 테스트 스크립트 목록 및 설명서 | 테스트 케이스 초안 작성 후 | 테스트 케이스 ID 체계 |
| 5 | 자동화 테스트 플랜 | 테스트 스크립트 후보가 정리된 직후 | CI 또는 로컬 실행 방식 후보 |
| 6 | 코드 리뷰 및 품질 관리 지침서 | 첫 구현 PR 전 | 코딩 표준, 품질 게이트 |
| 7 | 시뮬레이션 및 모의 환경 구성 문서 | 외부 OAuth, 스토리지, 검색 연동 테스트 전 | 모의 대상과 실제 의존성 구분 |
| 8 | 실행 및 로그 분석 가이드 | 하네스 실행 스크립트 초안 완성 후 | 로그 포맷, 결과 파일 위치 |

## 5. 권장 진행 순서

1. 프로젝트 산출물 3종을 기준선으로 검토한다.
2. 스토리지와 배포 운영 방식의 검토 필요 항목을 ADR 후보로 등록한다.
3. 하네스 기획서에서 요구사항 ID별 검증 가능성을 매핑한다.
4. DB/API/UI 문서를 병렬로 상세화하되, 인증/계정 통합은 우선 확정한다.
5. 테스트 케이스와 하네스 테스트 스크립트를 ID로 연결한다.
6. 첫 구현 PR 전 코드 리뷰 및 품질 관리 지침서를 확정한다.
