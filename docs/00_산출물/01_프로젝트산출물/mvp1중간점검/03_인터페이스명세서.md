# 03. MVP1 인터페이스 명세서

## 1. 범위

본 명세서는 `src/review/mvp1-review-server.ts`에 구현된 MVP1 검수 서버 HTTP 인터페이스를 기준으로 작성한다. 실제 서비스 API 확정 명세가 아니라 MVP1 인증/검수 구현의 중간 산출물이다.

## 2. 공통 규칙

| 항목 | 내용 |
| :--- | :--- |
| Base URL | 로컬 `http://localhost:4173`, dev NAS `https://jkok2.myqnapcloud.com:4443` |
| Content-Type | JSON API는 `application/json; charset=utf-8` |
| 세션 쿠키 | `pdfowers_review_session` |
| Kakao state 쿠키 | `pdfowers_kakao_state` |
| 성공 응답 | `{ ok: true, ... }` 또는 state JSON |
| 실패 응답 | `{ ok: false, error, state? }` |
| 민감정보 | OAuth token, client secret, authorization code는 응답/문서/로그에 기록하지 않음 |

### 3.2 `GET /api/review/state`

| 항목 | 내용 |
| :--- | :--- |
| 설명 | 현재 검수 상태 조회 |
| 인증 | 없음 |
| 주요 응답 필드 | `runId`, `users`, `mergeRequests`, `mergeRequestReviewItems`, `testCases`, `messages`, `notifications`, `database` |
| 비고 | persistence가 있으면 DB summary 반영 |

응답 예시:

```json
{
  "runId": "review-xxxxxxxx",
  "users": [],
  "mergeRequests": [],
  "mergeRequestReviewItems": [],
  "testCases": [{ "id": "MVP1-AUTH-T001", "title": "...", "status": "pending" }],
  "messages": ["검수 상태가 초기화되었습니다."]
}
```

### 3.3 `POST /api/review/reset`

| 항목 | 내용 |
| :--- | :--- |
| 설명 | 검수 상태 초기화 |
| 요청 Body | 없음 |
| 응답 | `{ ok: true, state }` |

### 3.4 `POST /api/review/scenarios/:scenarioId`

| 항목 | 내용 |
| :--- | :--- |
| 설명 | 사전 정의된 검수 시나리오 실행 |
| 요청 Body | 없음 |
| 응답 | `{ ok, scenarioId, message, state }` |
| 실패 | `REVIEW_SCENARIO_FAILED` |

지원 시나리오:

| scenarioId | 설명 |
| :--- | :--- |
| `local-signup` | ID/PW 회원가입 |
| `local-login-success` | ID/PW 로그인 성공 |
| `local-login-email-required` | 이메일 인증 필수 정책 안내 |
| `oauth-signup` | Mock OAuth 신규 가입 |
| `oauth-login` | Mock OAuth 기존 로그인 |
| `oauth-link-current-user` | 현재 계정 provider 연결 |
| `oauth-link-conflict` | 다른 계정 provider 충돌 및 통합 요청 생성 |
| `merge-approve` | 계정 통합 승인 |
| `merge-cancel` | 계정 통합 취소 |
| `merge-expire` | 계정 통합 만료 |
| `oauth-unlink` | OAuth 해제 |
| `verified-email-delete-blocked` | 인증 이메일 삭제 차단 |
| `email-change-confirm` | 이메일 변경 확인 |

## 4. 인증 API

### 4.1 `POST /auth/signup/local`

| 항목 | 내용 |
| :--- | :--- |
| 설명 | ID/PW 기반 로컬 사용자 생성 |
| 요청 Body | `loginId`, `email`, `password`, `displayName`, `emailVerified?` |
| 성공 | `200 { ok, user, state }`, `pdfowers_review_session` cookie |
| 실패 | `400 INVALID_SIGNUP_REQUEST`, `409 LOGIN_ID_ALREADY_EXISTS` |

요청 예시:

```json
{
  "loginId": "api-user",
  "email": "api-user@example.test",
  "password": "correct-password",
  "displayName": "API 사용자",
  "emailVerified": true
}
```

### 4.2 `POST /auth/login/local`

| 항목 | 내용 |
| :--- | :--- |
| 설명 | ID/PW 로그인 |
| 요청 Body | `loginId`, `password`, `emailVerificationRequired?` |
| 성공 | `200 { ok, user, state, emailVerification? }`, session cookie |
| 이메일 미인증 | 로그인은 성공 처리하고 `emailVerification.required=true`, `redirectTo=/user/profile` 또는 동등한 사용자정보 화면 이동 정보를 응답 |
| 실패 | `401 INVALID_CREDENTIALS` |

비고: 기존 도메인 테스트에는 `EMAIL_VERIFICATION_REQUIRED` 로그인 차단 흐름이 남아 있다. 최신 정책 기준 구현에서는 로그인 차단 대신 사용자정보 화면에서 이메일 인증을 안내해야 한다.

### 4.3 `POST /auth/email-verifications`

| 항목 | 내용 |
| :--- | :--- |
| 설명 | 이메일 인증번호 또는 인증 토큰 발급 및 발송 |
| 인증 | 회원가입 중에는 임시 가입 컨텍스트, 사용자정보 수정 화면에서는 session cookie 필요 |
| 요청 Body | `email`, `purpose` (`signup`, `profile`, `email_change`) |
| 성공 | `200 { ok, expiresAt, resendAvailableAt }` |
| 정책 | 만료 1시간, 재발송 시 기존 미완료 인증 폐기, 사용자+이메일 기준 60초 쿨다운과 1시간 최대 5회 발송 |
| 실패 | `400 INVALID_EMAIL_VERIFICATION_REQUEST`, `409 EMAIL_ALREADY_VERIFIED`, `429 EMAIL_VERIFICATION_RESEND_LIMITED` |

### 4.4 `POST /auth/email-verifications/confirm`

| 항목 | 내용 |
| :--- | :--- |
| 설명 | 이메일 인증번호 또는 인증 토큰 확인 |
| 요청 Body | `email`, `code` 또는 `token`, `purpose` |
| 성공 | `200 { ok, verifiedEmail, state? }` |
| 실패 | `400 INVALID_EMAIL_VERIFICATION_CONFIRM`, `409 EMAIL_VERIFICATION_EXPIRED`, `409 EMAIL_VERIFICATION_REVOKED`, `429 EMAIL_VERIFICATION_ATTEMPT_LIMITED` |

### 4.5 `GET /auth/email-verifications/status`

| 항목 | 내용 |
| :--- | :--- |
| 설명 | 현재 사용자 또는 가입 컨텍스트의 이메일 인증 상태 조회 |
| 응답 | `{ verified, email, required, notificationAvailable }` |

### 4.6 `GET /auth/session`

| 항목 | 내용 |
| :--- | :--- |
| 설명 | 현재 session cookie의 사용자 확인 |
| 응답 | `{ authenticated, user, state }` |

## 5. OAuth API

### 5.1 `POST /auth/oauth/:provider/callback`

| 항목 | 내용 |
| :--- | :--- |
| 설명 | Mock OAuth callback API. 검수화면에서 Kakao/Naver/Google 흐름을 시뮬레이션 |
| provider | `kakao`, `naver`, `google` |
| 요청 Body | `providerUserId`, `emailFromProvider?`, `loginId?`, `password?`, `displayName?` |
| 성공 | 기존 identity면 로그인, 신규 payload가 있으면 사용자 생성 |
| 실패 | `400 UNSUPPORTED_AUTH_PROVIDER`, `400 INVALID_OAUTH_CALLBACK_REQUEST`, `404 OAUTH_SIGNUP_REQUIRED` |

### 5.2 `GET /auth/kakao/config-status`

| 항목 | 내용 |
| :--- | :--- |
| 설명 | Kakao OAuth 설정 상태 확인 |
| 응답 필드 | `enabled`, `missing`, `redirectUri`, `redirectMode`, `scope`, `clientSecretConfigured` |
| 배포 검증 | `enabled=true`, `missing=[]` 기대 |

### 5.3 `GET /auth/kakao/start`

| 항목 | 내용 |
| :--- | :--- |
| 설명 | Kakao authorize URL로 redirect |
| 성공 | `302 Location: https://kauth.kakao.com/oauth/authorize...` |
| 실패 | `503 KAKAO_OAUTH_NOT_CONFIGURED` |
| 보안 | OAuth state 생성 및 `pdfowers_kakao_state` cookie 저장 |

### 5.4 `GET /auth/kakao/callback`

| 항목 | 내용 |
| :--- | :--- |
| 설명 | Kakao 실제 OAuth callback 처리 |
| Query | `code`, `state` |
| 성공 | token/profile 조회 후 `303 /?kakao=success`, session cookie |
| 실패 | `/?kakao_error=KAKAO_OAUTH_CODE_REQUIRED`, `KAKAO_OAUTH_STATE_MISMATCH`, `KAKAO_OAUTH_CALLBACK_FAILED` |

### 5.5 `GET /auth/:provider/start`

| 항목 | 내용 |
| :--- | :--- |
| 설명 | Kakao/Naver/Google 실제 OAuth authorize URL로 redirect하는 통합 후보 인터페이스 |
| provider | `kakao`, `naver`, `google` |
| 성공 | `302 Location: <provider authorize URL>` |
| 실패 | `400 UNSUPPORTED_AUTH_PROVIDER`, `503 OAUTH_PROVIDER_NOT_CONFIGURED` |
| 보안 | provider별 OAuth state 생성 및 쿠키 저장 |

### 5.6 `GET /auth/:provider/callback`

| 항목 | 내용 |
| :--- | :--- |
| 설명 | Kakao/Naver/Google 실제 OAuth callback 처리 후보 인터페이스 |
| Query | `code`, `state` |
| 성공 | token/profile 조회 후 session cookie 발급 또는 계정 통합 안내 |
| 실패 | provider별 code/state/profile 오류를 민감정보 없이 사용자 안내 코드로 변환 |

비고: 현재 실제 연동은 Kakao 전용 API가 먼저 구현되어 있다. Naver/Google 추가 시 provider별 전용 경로와 통합 경로 중 하나를 선택하되, 검수 시나리오와 오류 코드는 같은 의미 체계로 맞춘다.

## 6. 로그인 수단 연결 API

### 6.1 `POST /auth/identities/:provider`

| 항목 | 내용 |
| :--- | :--- |
| 설명 | 로그인 상태에서 provider identity 연결 |
| 인증 | `pdfowers_review_session` cookie 필요 |
| 요청 Body | `providerUserId`, `emailFromProvider?` |
| 성공 | `200 { ok, user, state }` |
| 통합 필요 | `409 ACCOUNT_MERGE_REQUIRED`, `mergeRequest`, `state.mergeRequestReviewItems` |
| 실패 | `401 AUTHENTICATION_REQUIRED`, `400 UNSUPPORTED_AUTH_PROVIDER`, `400 INVALID_IDENTITY_LINK_REQUEST`, `409 AUTH_IDENTITY_ALREADY_LINKED` |

### 6.2 `DELETE /auth/identities/:provider`

| 항목 | 내용 |
| :--- | :--- |
| 설명 | 로그인 상태에서 provider identity 해제 |
| 성공 | `200 { ok, user, state }` |
| 실패 | `401 AUTHENTICATION_REQUIRED`, `409 AUTH_IDENTITY_NOT_LINKED` |

## 7. 계정 통합 API

### 7.1 `POST /auth/merge-requests/:id/approve`

| 항목 | 내용 |
| :--- | :--- |
| 설명 | 계정 통합 요청 승인 |
| 인증 | session cookie 필요 |
| 성공 | `200 { ok, state }` |
| 성공 처리 | 대상 계정 identity 이전, 대상 계정 `merged`, audit log, 알림 이벤트 |
| 실패 | `401 AUTHENTICATION_REQUIRED`, `404 MERGE_REQUEST_NOT_FOUND`, `404 MERGE_USER_NOT_FOUND`, `409 MERGE_REQUEST_EXPIRED`, `409 MERGE_REQUEST_CANCELLED`, `409 MERGE_REQUEST_NOT_PENDING`, `409 DUPLICATE_MERGE_APPROVAL` |

### 7.2 `GET /auth/merge-requests`

| 항목 | 내용 |
| :--- | :--- |
| 설명 | 사용자정보 화면의 통합계정 목록 조회 |
| 인증 | session cookie 필요 |
| 응답 | 요청자 항목은 `요청`, `반려`, `완료`, 대상자 항목은 `요청`, `거절` 상태로 표시. 한 건도 없으면 빈 배열 반환 |

### 7.3 `POST /auth/merge-requests/:id/reject`

| 항목 | 내용 |
| :--- | :--- |
| 설명 | 대상자가 통합 요청 거절 |
| 인증 | session cookie 필요 |
| 성공 | `200 { ok, state }` |
| 실패 | `401 AUTHENTICATION_REQUIRED`, `404 MERGE_REQUEST_NOT_FOUND`, `409 MERGE_REQUEST_NOT_PENDING` |

### 7.4 `DELETE /auth/merge-requests/:id`

| 항목 | 내용 |
| :--- | :--- |
| 설명 | 통합정보 목록에서 삭제. 대상자 삭제는 자동 거절 처리하고, 요청자 삭제는 대상자 목록에서도 제거 |
| 인증 | session cookie 필요 |
| 성공 | `200 { ok, state }` |
| 실패 | `401 AUTHENTICATION_REQUIRED`, `404 MERGE_REQUEST_NOT_FOUND` |

## 9. 오류 코드

| 코드 | 의미 |
| :--- | :--- |
| `INVALID_CREDENTIALS` | 로그인 자격 증명 실패 또는 유효하지 않은 인증 상태 |
| `AUTH_IDENTITY_ALREADY_LINKED` | provider identity가 현재 계정에 이미 연결됨 |
| `ACCOUNT_MERGE_REQUIRED` | provider identity가 다른 계정에 연결되어 통합 필요 |
| `LOCAL_CREDENTIAL_REQUIRED` | 기본 ID/PW 삭제 차단 |
| `EMAIL_VERIFICATION_REQUIRED` | 기존 구현의 이메일 인증 필요 코드. 최신 정책에서는 로그인 차단 대신 사용자정보 화면 인증 안내로 대체 |
| `EMAIL_VERIFICATION_EXPIRED` | 이메일 인증번호 또는 인증 토큰 만료 |
| `EMAIL_VERIFICATION_REVOKED` | 재발송으로 기존 인증번호 또는 인증 토큰 폐기 |
| `EMAIL_VERIFICATION_RESEND_LIMITED` | 재발송 쿨다운 또는 시간당 발송 제한 |
| `EMAIL_VERIFICATION_ATTEMPT_LIMITED` | 인증번호 확인 실패 횟수 제한 |
| `VERIFIED_EMAIL_REQUIRED` | 인증 이메일 삭제 차단 |
| `AUTH_IDENTITY_NOT_LINKED` | 해제할 provider identity가 없음 |
| `MERGE_REQUEST_EXPIRED` | 통합 요청 만료 |
| `MERGE_REQUEST_CANCELLED` | 통합 요청 취소됨 |
| `MERGE_REQUEST_NOT_PENDING` | 통합 요청이 대기 상태가 아님 |
| `DUPLICATE_MERGE_APPROVAL` | 이미 승인된 통합 요청 재승인 |
