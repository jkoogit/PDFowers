# 요구사항 명세서

## 1. 목적

PDFowers의 전체 구현 대상을 요구사항 관점에서 정의한다. 본 문서는 [프로덕트 요구사항](../../02_기획관리/01_프로덕트요구사항.md#제품-목표), [시스템 정책](../../01_정책관리/01_시스템정책.md#1-회원-및-인증-정책), [도메인 설계](../../03_설계관리/03_도메인설계.md#도메인-목록), [ADR-003 인증 방식 선택](../../06_의사결정관리/ADR-003_인증방식선택.md#결정)을 기준으로 작성한다.

## 2. 제품 개요

PDFowers는 스캔 도서 PDF를 OCR, 목차, 주석, 버전 정보와 함께 관리하고 여러 기기에서 작업 연속성을 제공하는 PDF 작업 플랫폼이다. 사용자는 업로드한 PDF를 검색 가능한 디지털 자산으로 관리하고, 주석/목차/북마크/공유/버전 관리를 통해 장기 작업을 안정적으로 이어갈 수 있어야 한다.

## 4. 기능 요구사항

### FR-AUTH-001 ID 기반 회원계정

- 사용자가 입력하는 로그인 ID는 `login_id`로 관리한다.
- 시스템 내부 회원 식별자는 사용자가 알 수 없는 `user_srno`로 별도 관리한다.
- `user_srno`는 UUID 사용을 기본 후보로 한다.
- 사용자는 가입 시 서비스 로그인용 ID와 비밀번호를 등록해야 한다.

### FR-AUTH-001-1 이메일 로그인 및 인증 이메일

- 이메일은 회원가입과 로그인 시 인증 수단으로 사용할 수 있어야 한다.
- ID 가입 또는 간편로그인 가입 상태에서도 사용자 화면에서 이메일 인증을 수행할 수 있어야 한다.
- 이메일 회원가입 시에도 서비스 로그인용 ID와 비밀번호를 필수 입력해야 한다.
- 이메일은 계정 조회와 식별의 근거로 사용할 수 있으나, 이메일 동일성만으로 계정을 자동 통합하지 않는다.
- 시스템 알림은 인증되고 수신 동의한 이메일에만 발송한다.
- 시스템은 문서 공유, 작업 변경, 권한 변경, 처리 실패 등 작업 알림을 우선 이메일로 발송할 수 있어야 한다.
- 카카오 알림톡은 후속 알림 채널 후보로 검토하며, 비용 발생 여부를 확인해야 한다.

### FR-AUTH-002 간편로그인

- MVP 후보 간편로그인 제공자는 카카오, 네이버, 구글이다.
- 각 제공자는 OAuth 또는 OIDC 기반으로 연동한다.
- 제공자별 사용자 식별자는 `(provider, provider_user_id)`로 관리한다.
- 간편로그인 기반 회원가입 시에도 서비스 로그인용 ID와 비밀번호를 필수 입력해야 한다.

### FR-AUTH-003 로그인 수단 연결

- 사용자는 로그인한 상태에서 추가 간편로그인을 연결할 수 있다.
- 연결 대상 `(provider, provider_user_id)`가 미사용이면 현재 로그인한 `user_srno`에 연결한다.
- 이미 현재 계정에 연결된 수단이면 `AUTH_IDENTITY_ALREADY_LINKED` 상태를 반환한다.
- 다른 내부 계정에 연결된 수단이면 자동 연결하지 않고 `ACCOUNT_MERGE_REQUIRED` 상태를 반환한다.
- 다른 내부 계정에 연결된 수단이면 대상 계정으로 병합 요청을 보내고, 대상 계정으로 로그인한 사용자가 수용한 뒤 병합을 진행한다.

### FR-AUTH-004 계정 통합

- 계정 통합은 사용자의 명시적 동의가 있을 때만 수행한다.
- 통합 전 두 계정의 주요 데이터 범위와 되돌리기 어려운 항목을 안내한다.
- 대표 계정을 기준으로 AuthIdentity, 문서, 주석, 공유 권한, 설정을 이전한다.
- 보조 계정은 물리 삭제하지 않고 `merged` 상태와 `merged_into_user_srno`를 남긴다.
- 통합 전후 감사 로그를 기록한다.
- 통합 승인 화면은 통합되는 정보 범위와 동의 여부를 대상 계정 사용자에게 확인시켜야 한다.

### FR-DOC-001 문서 생명주기

- 사용자는 PDF 문서를 업로드할 수 있어야 한다.
- 시스템은 문서의 소유자, 제목, 상태, 생성/수정 일시 등 메타데이터를 관리해야 한다.
- 문서 삭제, 보관, 공유 상태는 감사 가능하게 관리되어야 한다.

### FR-PDF-001 PDF 처리

- 시스템은 원본 PDF를 보관해야 한다.
- 업로드 시 시스템은 페이지 이미지, PDF에 등록된 주석, PDF에 등록된 OCR 데이터를 원본 PDF와 분리해 관리해야 한다.
- 신규 목차 생성과 미등록 OCR 생성은 업로드 처리와 분리된 별도 프로세스로 진행한다.
- 다운로드 시 원본과 변경 데이터를 결합하여 표준 PDF로 내보낼 수 있어야 한다.
- 다운로드 파일명은 `[도서명]_[버전]_[수정일자]_[수정시간].pdf` 형식을 기본 후보로 한다.
- 다운로드한 PDF를 다시 업로드할 때 문서, 버전, 리소스 동일성을 검증할 수 있어야 한다.

### FR-ANNOTATION-001 주석 관리

- 사용자는 문서 페이지 또는 선택 영역에 주석을 생성, 조회, 수정, 삭제할 수 있어야 한다.
- 주석은 작성자와 변경 이력을 추적할 수 있어야 한다.
- 계정 통합 시 주석 작성자 ID 이전 원칙을 적용해야 한다.
- 주석 작성자 정보는 기본 계정 기준으로 관리하되, 문서별 작성자명/표시명 관리 가능성을 검토한다.
- 사용자는 주석 대상 영역을 이미지로 캡처하거나 붙여넣고, 해당 영역의 주석 텍스트를 수정 또는 검색할 수 있어야 한다.
- 주석 영역 편집은 OCR 처리 기능이 아니라 주석 편집 기능의 일부로 관리한다.

### FR-SHARING-001 공유 관리

- 사용자는 문서를 다른 사용자에게 공유할 수 있어야 한다.
- 공유 권한과 만료 조건을 관리할 수 있어야 한다.
- 계정 통합 시 공유 권한은 대표 계정 기준으로 재연결되어야 한다.
- 공유 링크는 대상 문서/버전, 공유 기간, 읽기/주석/댓글/수정 권한을 포함해야 한다.
- 공개 읽기 링크는 구현 대상이다.
- 공개 읽기 링크를 기본 서비스 화면 권한으로 제공할지, 별도 공개 읽기 화면으로 제공할지는 설계 단계에서 결정한다.
- 백엔드 API도 기존 문서 조회 API에 권한 처리를 확장할지, 별도 공개 읽기 전용 API를 구성할지 설계 단계에서 결정한다.

### FR-SYNC-001 작업 연속성

- 사용자는 여러 기기에서 동일 문서 작업을 이어갈 수 있어야 한다.
- 오프라인 변경과 충돌 해결은 별도 상세 설계에서 확정한다.

### FR-AI-001 AI 검색 연동

- AI 검색은 본인인증이나 계정 식별 기능이 아니다.
- 사용자가 선택한 텍스트 또는 직접 입력한 키워드만 외부 검색 질의로 전달한다.
- 문서 전체, 개인정보, 인증정보를 자동 전송하지 않는다.
- MVP 필수 기능 여부는 별도 우선순위 검토 후 확정한다.

## 6. MVP 범위

### 단계적 MVP

| 단계 | MVP 범위 | 핵심 내용 |
| :--- | :--- | :--- |
| 1차 | 인증/간편로그인 | 회원가입(ID/이메일/간편로그인), 로그인(ID/이메일/간편로그인), 계정 통합 |
| 2차 | PDF 문서 | 업로드 시 이미지/OCR/주석 분리, 다운로드 시 이미지/OCR/주석 통합 |
| 3차 | 주석 편집 | 주석 편집과 실시간 동기화 |
| 4차 | 공유 설정 | 문서 공유 대상과 권한 설정 |
| 5차 | 협업 작업 구성 | 동시 수정 기반 협업 작업 |
| 6차 | 오프라인 작업 | 작업 중 오프라인, 오프라인 업로드, 온라인 전환 |
| 7차 | PDF OCR 처리 | OCR 처리 품질과 자동화 고도화 |

### 1차 MVP 포함

- ID 기반 회원계정 생성
- 이메일 기반 로그인
- 인증 이메일 등록 및 작업 알림 발송 대상화
- 카카오 간편로그인
- 네이버 간편로그인
- 구글 간편로그인
- ID/이메일/간편로그인 기반 로그인
- 이메일 회원가입 및 간편로그인 회원가입 시 ID/PW 필수 입력
- 로그인 상태에서 간편로그인 수단 추가 연결
- 동일 벤더 ID가 다른 내부 계정에 연결된 경우 계정 통합 안내
- 로그인한 계정을 중심으로 대상 계정을 선택하는 사용자 동의 기반 계정 통합

### 제외

- 휴대폰 본인확인
- 실명확인
- 주민등록 기반 동일인 인증
- 2차 인증
- 이메일 동일성만으로 자동 계정 통합
- 전화번호 동일성만으로 자동 계정 통합
