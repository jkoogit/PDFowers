# 하네스 작업 운영 절차

## 1. 목적

세션 마무리, 브랜치 승급처럼 반복되는 프로젝트 운영 작업을 하네스 작업으로 등록하고, 실행 순서와 산출물을 추적 가능하게 관리한다.

## 3. 세션 마무리 절차

`#세션 마무리`를 새로 정의하거나 절차를 변경하는 요청은 먼저 본 문서에 하네스 작업프로세스로 등록한 뒤, 등록된 절차에 따라 실행한다.

| ID | 순서 | 작업 | 처리 기준 |
| :--- | :---: | :--- | :--- |
| `00020903_001` | 1 | 세션명 정리 | 세션번호를 유지하고 세션 작업 내용을 반영해 `세션번호-작업내용` 형식으로 정리한다. |
| `00020903_002` | 2 | 작업 리뷰 문서 작성 | 이번 작업 요약, 변경 문서, 검증 내용, 다음 작업 목표와 범위를 기록한다. |
| `00020903_003` | 3 | 이슈 등록 | 작업 배경, 목표, 범위, 완료 조건, 관련 문서를 포함해 GitHub 이슈를 생성한다. 신규 이슈는 생성 후 제목 앞에 `#이슈번호`를 표시하도록 갱신한다. |
| `00020903_004` | 4 | PR 생성 | 작업 브랜치를 push하고 `dev` 브랜치를 대상으로 PR을 생성한다. PR 제목에는 관련 이슈 번호를 포함하고, PR 본문에는 `Closes #번호` 또는 명확한 이슈 참조를 포함한다. |
| `00020903_005` | 5 | 관련 문서 현행화 | 세션 작업과 관련된 운영 기준, 이슈/잔여작업, 리뷰, 하네스 산출물, 스킬 문서를 점검하고 필요한 변경을 반영한다. |

## 4. 브랜치 승급 절차

| ID | 순서 | 작업 | 처리 기준 |
| :--- | :---: | :--- | :--- |
| `00020904_001` | 1 | `dev` 병합 | 세션 작업 PR을 `dev`에 병합한다. |
| `00020904_002` | 2 | `dev` to `stg` 직접 승급 | 별도 승급 PR 없이 `dev` 변경을 `stg`로 직접 머지한다. |
| `00020904_003` | 3 | `stg` to `main` 직접 승급 | 별도 승급 PR 없이 `stg` 변경을 `main`으로 직접 머지한다. `main`은 운영서비스 prd에 해당한다. |
| `00020904_004` | 4 | 승급 메시지 기록 | 머지 메시지와 이슈 댓글에 이슈번호, 원천 PR번호, 승급 머지 SHA를 표시한다. |
| `00020904_005` | 5 | 브랜치 점검 | 원격 `dev`, `stg`, `main`과 로컬 `main`의 commit/tree 상태를 확인한다. |
| `00020904_006` | 6 | 이슈 종료 | 세션 내 작업한 이슈의 완료 조건을 확인하고 닫는다. |
